# ZombiePlague.Core

Ядро Zombie Plague для CS2 и SwiftlyS2 — классы, роли, заражение, режимы и способности

## Каталог классов и способностей

Начиная с 0.3.0, классы людей и зомби, способности и персональные назначения читаются из PostgreSQL через подключение SwiftlyS2 `elysium_zp_server_1`
Админка `ElysiumZombieClasses` использует подключение к той же игровой БД из реестра `ElysiumEquipments`

Каталог загружается целиком одним SELECT: определения классов, способности, связи, назначения SteamID64 и версия
Сервер валидирует весь снимок до его замены, поэтому частичное сохранение не меняет игру

| Триггер | Действие |
|---|---|
| Загрузка плагина | Загрузить БД или fallback до запуска игрового координатора |
| Начало карты | Обновить каталог до precache моделей и частиц |
| `zp_classes_reload` | Обновить классы, способности и персональные назначения |
| `zp_abilities_reload` | То же обновление полного каталога |
| `zp_classes_status` | Показать источник, версию, число записей и ожидание новых ресурсов |

Команды требуют `zombie_plague.admin.classes` и доступны из серверной консоли
Периодического опроса БД и слежения за изменениями fallback нет
Параллельные команды объединяются в один выполняющийся запрос, выгрузка отменяет и завершает его
`OnMapLoad` и precache одной карты используют общий запрос, даже если первый уже успел завершиться до второго события
Подключение и SQL ограничены тайм-аутами по 5 секунд

При ошибке БД сервер заново читает `configs/ZombiePlague.Core/zombie_catalog.json` относительно SwiftlyS2
Если оба источника недоступны или не проходят проверку, сохраняется последний рабочий снимок в памяти
При первом запуске без единого рабочего источника плагин не запускает игровой координатор и пишет ошибку

Новый снимок используется при следующем создании роли, включая заражение, начало раунда и пересоздание обычного зомби при респавне
Существующие роли сохраняют свой набор до пересоздания
Если reload добавляет ещё не зарегистрированные модели или частицы, полный снимок ожидает precache следующей карты — `pending_resources` виден в статусе
При горячей загрузке плагина посреди карты новые игровые ресурсы требуют смены карты

## Персональные способности и стороны

В `PlayerAbilities` хранится одна запись на SteamID64 со списком ключей способностей
SteamID64 передаётся строкой, чтобы JavaScript не округлял идентификатор

```json
{
  "SteamId": "76561198000000001",
  "DisplayName": "Ник игрока",
  "Enabled": true,
  "Abilities": ["heal", "double_jump"]
}
```

При создании роли сервер объединяет список класса и личный список игрока по `InternalName`, отбрасывает выключенные и недоступные для текущей стороны способности, затем создаёт объекты
Совпавший ключ даёт ровно один экземпляр, одну подписку на ввод и один cooldown
У разных игроков и вновь создаваемых ролей собственные объекты способностей
Снятие личного назначения не снимает ту же способность, если она осталась у класса

| `Side` способности | Доступ |
|---|---|
| `human` | Люди, включая Survivor |
| `zombie` | Зомби, включая Nemesis |
| `both` | Люди и зомби |

Ограничение одинаково действует на способности класса и личные назначения
Неактивная на текущей стороне личная способность сохраняет назначение и станет доступна после подходящего превращения
В старом экспорте без `Side` используется `both`
В базовом каталоге Leap доступен обеим сторонам, Double Jump людям, остальные способности зомби — это сохраняет штатные наборы Survivor и обычных классов

`InternalName` определяет уникальность способности, а `Kind` — её серверную механику
Поддерживаются `heal`, `leap`, `blind`, `charge`, `trap`, `catch`, `double_jump`
Можно создавать несколько записей одной механики с разными ключами и параметрами
Они считаются разными способностями; активные способности на E срабатывают вместе
Новая механика требует реализации в плагине и описания параметров в веб-модуле
Ловушка работает против противоположной команды и поддерживает назначение обеим сторонам

`Side` ограничивает владельца, выбор цели задаёт механика
Heal лечит другого живого союзника под прицелом до его максимального HP: человек лечит человека, зомби — зомби
Чтобы человек получил Heal, назначьте его игроку или человеческому классу и разрешите `human` либо `both`

## Человеческие классы

Формат 2 объединяет `human`, `zombie`, `survivor` и `nemesis` в одном каталоге
`DefaultHumanClass` и `SurvivorClass` дополняют `DefaultClass` и `NemesisClass`
Обычные человеческие классы выбираются через `hclass` / `humanclass`, выбор сохраняется по SteamID64
Специальные классы скрыты из обычного выбора и сохраняют поведение режимов
Для людей настраивается броня `Armor`, пустой `Model` сохраняет стандартную модель
`human_class.json` используется только при переносе формата 1 или создании первого fallback, дальнейшее управление идёт из общего каталога

## Установка и перенос

1. Установить пакет сервера 0.3.0 вместе с обновлённым `Localization.Core` и сохранить существующие файлы конфигурации
2. Запустить сервер — он создаст недостающие таблицы и заполнит пустую БД из fallback либо преобразованных старых файлов
3. Существующий каталог формата 1 обновится с переносом Mercenary и Survivor из `human_class.json`, без замены настроек зомби, способностей и игроков
4. Установить `ElysiumZombieClasses` 1.1.0 и `ElysiumLocalization` 1.9.1 на сайт, открыть **Elysium → Классы**
5. Проверить классы, скачать актуальный fallback и установить его в `configs/ZombiePlague.Core/zombie_catalog.json`
6. Выполнить `zp_classes_reload`, при новых ресурсах сменить карту, проверить `zp_classes_status`

DDL в `src/Catalog/schema.sql` совпадает с веб-модулем
Сервер применяет его при отсутствии таблиц или переносе старого каталога, затем повторно читает состояние под общим с сайтом транзакционным замком
Инициализированный формат 2 читается без DDL и без обращения к fallback
Для первого создания/обновления игровому подключению нужны права создания схемы, таблиц и записи каталога
Сайт сохраняет создание схемы через импорт или кнопку «Создать базовый каталог» — повторная инициализация не меняет опубликованные данные
Технические имена таблиц, модуля, маршрута и fallback сохранены для совместимости
Новый формат требует обновления обеих частей; старый плагин 0.2.x его не читает

Если `zombie_catalog.json` отсутствует, плагин преобразует `zombie_class.json` + `ability.json` и `human_class.json`
При отсутствии старых файлов используются встроенные значения: шесть зомби-классов, Наёмник, Выживший и семь способностей
Повреждённые файлы не заменяются стандартными значениями, исходники переноса не перезаписываются
В старом human-конфиге повторные и отсутствующие ключи способностей нормализуются так же, как это делала прежняя фабрика
Новый формат проверяет ссылки строго

## Localization и превью

`DisplayNameKey` и `DescriptionKey` обязательны у классов и способностей
Игровое меню получает перевод через `ILocalizationApi`, при отсутствии перевода показывает ключ
Старые `DisplayName` и `Description` допускаются только как источник переноса, игровое меню их не использует
При переносе отсутствующие записи добавляются в готовую схему Localization без перезаписи существующих переводов
Обновлённый `Localization.Core` содержит базовые ключи ru/en, человеческое меню и fallback с корректной контрольной суммой
После собственных изменений переводов нужно также обновить fallback модуля Localization

Веб-редактор показывает перевод, позволяет открыть конкретный ключ в Localization или создать недостающий
Служебный ID не является пользовательским названием
GLB используется только для веб-превью, игровой VMDL должен быть в установленном addon

## Если каталог работает из fallback

`42P01` означает отсутствие таблицы в выбранной БД, а не обязательно обрыв подключения
При недостаточных правах автоматического создания проверьте права игрового подключения либо импортируйте каталог через сайт
Сверьте хост, порт и имя игровой БД для SwiftlyS2 `elysium_zp_server_1` и выбранного веб-сервера
Ожидаемый результат `zp_classes_status` — `source=database` и версия больше нуля
При `pending_resources` смените карту
Если есть определения классов, но потеряна строка опубликованных настроек, автоматическое заполнение останавливается, чтобы не заменить осиротевшие данные — восстановите настройки из резервной копии

## Уведомление о заражении

Начиная с 0.3.0, уведомление в ленте убийств использует штатную иконку `knife`
Ключ `biohazard` заставлял CS2 искать отсутствующий `panorama/images/icons/equipment/biohazard.vsvg`
Это клиентское событие через `GameEvent.FireAsync`, серверная статистика заражений обновляется отдельным `PlayerInfectedContext`
Иконка не требует установки дополнительного VPK и не относится к HUD способностей

Если предупреждение `biohazard.vsvg` возникает при загрузке карты до появления игроков, проверить также `plugins/ZombiePlague.Core/ResourceLoader/resources.json` относительно SwiftlyS2
VSVG не является допустимым типом для игрового precache — такие записи теперь пропускаются с одной подсказкой при загрузке плагина
Сам файл не перезаписывается, запись иконки следует удалить из списка `PrecacheResources`

`Failed loading resource ... (ERROR_FILEOPEN: File not found)` для VMDL, графов анимации и звуков означает, что конкретного файла нет по запрошенному пути среди смонтированных ресурсов
Проверить пути из каталога и `ResourceLoader/resources.json`, включая регистр символов, и полный состав VPK с зависимостями моделей
Успешное монтирование addon само по себе не подтверждает наличие каждого запрошенного файла
Такие ошибки плагин не скрывает — без самих ресурсов модель или звук не появятся

## Проверка и сборка

```powershell
pwsh ./scripts/build-package.ps1 -Configuration Release
dotnet test CS2ZombiePlague.sln --configuration Release --no-build --no-restore
```

Тесты каталога проверяют загрузку и восстановление БД, перечитывание fallback, отмену, миграцию старых настроек, валидацию, уникальность персональных назначений, объединение способностей, стороны и отложенный precache ресурсов

## HUD способностей

Штатная панель через `custom_hud_layout` включена по умолчанию и остаётся видимой при открытом меню SwiftlyS2
Личные размер и положение доступны через `!hud` / `zp_hud`; пунктов HUD и выбора класса людей в главном меню нет
Работающий VPK с ресурсами v4 совместим с версией 0.4.0 без пересборки
