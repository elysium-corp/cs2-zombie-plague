# Ability Buff HUD — эксперимент

Ветка `experiment/ability-buff-hud`, версия ядра `0.2.1-hud.1`
Эксперимент расширяет каталог классов и личных способностей из PR #86 и выключен по умолчанию

## Что показывает

Внизу по центру, выше стандартного HUD, появляется панель Elysium с иконками принадлежащих игроку способностей
Готовые способности подсвечены зелёным, пассивные голубым, перезарядка затемняет иконку и показывает оставшиеся секунды
Под активной способностью указан ввод: E или CTRL+SPACE
Названия можно включить настройкой `ShowNames`

Панель получает уже созданные экземпляры способностей текущей роли
Поэтому личная выдача, способности класса, ограничение human/zombie/both и отсутствие дублей совпадают с игровым поведением
Ключ способности берётся из её экземпляра: новый каталог после reload не переименовывает старую роль и не подменяет её cooldown
Два разных ключа одной механики показываются отдельно, одинаковый ключ один раз
Скрытые из-за лимита иконок способности продолжают работать — число оставшихся показывает `+N`

Это индикатор доступных способностей, а не реестр наложенных на игрока эффектов вроде ослепления чужой способностью
Готовность отражает cooldown; дополнительные условия применения, например земля под ногами или подходящая цель, проверяет сама способность
Нажатие на иконки не предусмотрено, ввод мыши HUD не захватывает
При смерти, отсутствии роли и открытом меню панель скрывается
При превращении меняется набор, при выходе очищаются персональные значения слота

## Требования

Нужен CS2 с `custom_hud_layout` и SwiftlyS2 с публичными методами:

- `CCSCustomHudLayout.SetDialogVariableStringForPlayer`
- `CCSCustomHudLayout.SetHasClassForPlayer`
- `CCSCustomHudLayout.SetInputCaptureEnabled`

В закреплённом SDK `1.4.6-beta.8` есть схема сущности, но этих методов ещё нет
Наличие методов подтверждено в NuGet `1.4.10-beta.3`; совместимость проверяется по API установленного runtime, а не только по номеру версии
Старый runtime продолжает загружать ядро, попытка включить HUD сообщает причину и останавливает только эксперимент
Нет ручных смещений памяти и собственных сигнатур движка — используются публичные методы SwiftlyS2 через однократно связанные делегаты

Исходники контракта и документация:

- [SwiftlyS2 Custom HUD](https://swiftlys2.net/docs/development/custom-hud/)
- [Реализация API на игровом потоке](https://github.com/swiftly-solution/swiftlys2/blob/ce37bdc8f26ce98059eb2cef72bbd479c4504b1e/managed/src/SwiftlyS2.Core/Modules/Schemas/Extensions/CCSCustomHudLayoutImpl.cs)
- [Valve: добавление custom_hud_layout](https://www.counter-strike.net/news/updates)

## Panorama и addon

Содержимое `content/` — исходники для CS2 Workshop Tools:

```text
content/panorama/layout/custom_game/elysium_ability_buffs.xml
content/panorama/styles/custom_game/elysium_ability_buffs.css
content/panorama/images/custom_game/elysium/abilities/*.svg
```

Иконки нарисованы для этого эксперимента, сторонние изображения и шрифты в комплект не добавлены
Разметка использует Panel, Image, Label и CSS, без клиентского JavaScript
Каждый из 12 слотов содержит изображения известных механик; сервер выбирает изображение CSS-классом
Это не зависит от поддержки динамической подстановки URL в Image

1. Открыть существующий addon в CS2 Workshop Tools
2. Скопировать содержимое `content/` в `Counter-Strike Global Offensive/content/csgo_addons/ИМЯ_ADDON/`, сохранив пути
3. Скомпилировать Panorama XML, CSS и изображения инструментами ресурсов Workshop Tools
4. Убедиться, что в `game/csgo_addons/ИМЯ_ADDON/panorama/` появились скомпилированные ресурсы, включая `layout/custom_game/elysium_ability_buffs.vxml_c` и `styles/custom_game/elysium_ability_buffs.vcss_c`
5. Включить весь скомпилированный набор Panorama в VPK своего addon и обновить его у сервера и клиентов штатным способом
6. Установить экспериментальный `ZombiePlague.Core`, сменить карту и включить HUD командой ниже

Размещение XML рядом с DLL недостаточно — клиент должен получить ресурсы через игровой addon
Сервер проверяет наличие скомпилированного layout в смонтированной файловой системе GAME перед созданием сущности
Папка исходников включается в пакет плагина для удобства переноса, но не монтируется автоматически
Готового скомпилированного VPK здесь нет: Workshop Tools и игровой клиент в среде разработки недоступны

## Включение

Серверная консоль или администратор с `zombie_plague.admin.classes`:

```text
zp_ability_hud on
zp_ability_hud status
zp_ability_hud off
```

Команда `on` ставит создание HUD на следующий игровой кадр, после неё повторный `status` показывает результат
Она не изменяет конфиг на диске
`off` отменяет таймер и удаляет принадлежащую эксперименту сущность HUD
Ошибка API/ресурсов/обновления останавливает эксперимент с одним сообщением в логе, повторная попытка — через `on`

Для автоматического включения при загрузке плагина изменить `configs/ZombiePlague.Core/ability_hud.json` относительно SwiftlyS2:

```json
{
  "AbilityHud": {
    "Enabled": true,
    "RefreshSeconds": 0.25,
    "MaximumIcons": 8,
    "ShowNames": false,
    "HideWhenMenuOpen": true
  }
}
```

Конфиг читается при загрузке плагина, автоматического отслеживания файла нет
`RefreshSeconds`: 0.1–2 секунды, `MaximumIcons`: 1–12
При смене карты включённый эксперимент создаёт новую сущность
Положение панели и размер иконок меняются в CSS с последующей пересборкой addon

## Нагрузка и проверка

Одна сущность custom_hud_layout обслуживает игроков через персональные состояния
Проверка способностей выполняется по игровым тикам раз в 0.25 секунды, запросов в БД из HUD нет
Неизменившиеся значения не отправляются повторно, число панелей и имён переменных фиксировано
HUD только читает состояние способностей, не вызывает Use, Hook, StartCooldown и не меняет игровые таймеры

Автотесты проверяют идентичность и дедупликацию, cooldown, пассивные способности, переполнение, отсутствие повторных отправок, смену роли, очистку слота и соответствие целей сервера разметке
Сборка C# не проверяет компиляцию Panorama и фактическое отображение внутри CS2

На тестовом сервере проверить:

- Два игрока с разными наборами видят каждый свои иконки
- Совпавшая личная и классовая способность показана один раз
- E/CTRL+SPACE запускают обычную способность, её cooldown появляется и заканчивается
- Заражение и Survivor/Nemesis меняют иконки согласно стороне
- Смерть, меню, отключение и повторный вход не оставляют старых иконок
- `off`, смена карты и выгрузка плагина убирают старую панель
- Иконки читаются на используемых разрешениях и не закрывают прицел, чат и магазин
