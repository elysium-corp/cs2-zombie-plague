# Ability HUD — эксперимент

Ветка `experiment/ability-buff-hud`, PR #87, версия ядра `0.3.1-hud.4`, база `develop`
Эксперимент выключен по умолчанию и совместим с общим каталогом классов людей и зомби

## Правило отображения

Показываем все **фактически созданные способности текущей роли конкретного игрока**
Это уже объединённый набор способностей класса и личных выдач с фильтрацией `human` / `zombie` / `both`
Одинаковый ID отображается один раз; разные ID одной механики остаются разными способностями
Не назначенные игроку способности из каталога, отключённые определения и выдачи других игроков в панель не попадают
Отдельный список способностей в конфиге HUD не нужен

| Состояние | Отображение |
| --- | --- |
| Активная способность без КД | Зелёная иконка и клавиша E либо CTRL+SPACE |
| Пассивная способность без КД | Голубая иконка и отметка ∞ |
| Способность на КД любого типа | Затемнённая иконка с оставшимися секундами; отметка типа сохраняется |
| Нет способностей или нет живой роли | Панель скрыта |

КД читается из игрового экземпляра и округляется вверх до целой секунды
HUD не вызывает `Use`, не запускает таймеры способностей и не меняет их поведение
Подсветка означает отсутствие КД; цель, расстояние, состояние на земле и другие условия проверяет сама способность
У Double Jump есть дополнительное условие повторного прыжка до приземления — HUD не является счётчиком таких зарядов
Эффекты, наложенные чужими способностями, отдельными баффами здесь не показываются

Панель находится внизу по центру, выше штатного HUD
Сначала идут активные способности, затем пассивные; запуск и окончание КД не меняют порядок
Без заголовка, пустых слотов и счётчика `+N`
Весь допустимый каталогом набор помещается в 48 слотов: до 16 способностей класса + 32 личных, по 8 в строке
Неиспользуемые строки и иконки скрыты; `MaximumIcons` из старого эксперимента больше не применяется
Иконки обозначают механику, названия различают собственные варианты одной механики

Названия берутся из `DisplayNameKey` через `ILocalizationApi` для языка получателя
При изменении перевода подпись обновляется без перезагрузки HUD; старое текстовое поле `DisplayName` не используется
При отсутствии перевода показывается ключ, как в игровом меню
Настройка `ShowNames: false` скрывает подписи

Заражение, лечение и смена роли переключают панель на новый набор, включая Survivor и Nemesis
При смерти и открытии обычного меню она скрывается, при отключении очищаются персональные значения
Меню настройки HUD сохраняет предпросмотр для живого игрока с назначенными способностями
Обновление каталога применяется к HUD тогда же, когда реально пересоздаётся роль: старый экземпляр сохраняет свои ID, ключ названия и КД

## Персональный размер и положение

Игрок открывает `!hud` в чате или `zp_hud` в клиентской консоли
Также доступен пункт «Панель способностей» в главном игровом меню, когда эксперимент включён на сервере
Администраторское право для личных настроек не нужно

- Размер: 50%, 75% или 100%
- Положение: девять позиций — слева/по центру/справа, сверху/посередине/снизу
- «Сбросить расположение и размер»: 100%, снизу по центру
- «Готово»: закрыть меню

Переключатели используют штатные клавиши игрового меню, изменение сразу отражается в предпросмотре
Предпросмотр показывает только настоящие способности живого игрока, без добавления демонстрационных иконок
Свободное перетаскивание мышью не реализовано; позиция выбирается из девяти точек

Выбор хранится по SteamID в общей сессии настроек игрока и сохраняется в `zombie_plague.players` штатно при выходе или выгрузке плагина
Серверная EF-миграция `20260906160000_AddAbilityHudPreferences` добавляет `ability_hud_scale` и `ability_hud_position` с прежним видом по умолчанию
Поздняя загрузка из БД не перезаписывает уже сделанную настройку, включая явный сброс
При недоступной БД работают значения текущей сессии; для сохранения между подключениями требуется успешная загрузка и запись настроек

Тексты меню и названия позиций находятся в Localization под `Menu.AbilityHud.*`
Обновить `Localization.Core` вместе с ядром: он добавляет ключи ru/en миграцией без замены пользовательских переводов и содержит обновлённый fallback

## Требования

- Актуальный CS2 с сущностью `custom_hud_layout`
- SwiftlyS2 с публичными `SetDialogVariableStringForPlayer`, `SetHasClassForPlayer`, `SetInputCaptureEnabled`
- `Localization.Core` версии `1.5.4-hud.1` и зависимости `ZombiePlague.Core` из этой ветки
- Скомпилированные Panorama-ресурсы v3, доступные **и серверу, и клиенту** через смонтированный игровой addon

Закреплённый в `develop` SDK SwiftlyS2 `1.4.9` содержит необходимые методы — для HUD не требуется отдельное повышение версии SDK
Runtime сервера тоже должен предоставлять эти методы
При несовместимом runtime или отсутствующих ресурсах останавливается эксперимент, причина выводится в лог и `zp_ability_hud status`
Проверка API и связывание делегатов выполняются при старте, без ручных смещений памяти

[Официальный контракт Custom HUD в SwiftlyS2](https://swiftlys2.net/docs/development/custom-hud/)
описывает персональные состояния и требование выполнять изменения на игровом потоке

## 1. Установить экспериментальный плагин

Из корня репозитория на ветке `experiment/ability-buff-hud`:

```powershell
pwsh ./scripts/build-package.ps1 -Configuration Release
```

Папки для сервера находятся в `dist/Release/plugins/`, ZIP — в `dist/Release/packages/`
Обновить `ZombiePlague.Core` целиком, а зависимости — до совместимого актуального комплекта
Не заменять существующие пользовательские конфиги шаблонами
Путь к плагину относительно SwiftlyS2: `plugins/ZombiePlague.Core/`

В пакет входит `resources/experimental/ability-hud/` с этой инструкцией и исходниками Panorama
Сборка .NET не компилирует их в игровые ресурсы и не монтирует addon

## 2. Скомпилировать Panorama в Workshop Tools

1. Установить CS2 Workshop Tools и открыть свой addon, например `elysium_dev`
2. Скопировать **содержимое** `content/` из этой папки в `Counter-Strike Global Offensive/content/csgo_addons/elysium_dev/`, сохранив пути и регистр
3. Скомпилировать эти XML, CSS и SVG инструментом ресурсов Workshop Tools
4. Проверить результат в `Counter-Strike Global Offensive/game/csgo_addons/elysium_dev/panorama/`

После копирования исходников компиляцию можно вызвать из PowerShell, указав свой путь к игре:

```powershell
$cs2Path = 'C:\Program Files (x86)\Steam\steamapps\common\Counter-Strike Global Offensive'
$hudSource = Join-Path $cs2Path 'content/csgo_addons/elysium_dev/panorama'
$resourceCompiler = Join-Path $cs2Path 'game/bin/win64/resourcecompiler.exe'
$hudInputs = @(
    'images/custom_game/elysium/abilities/*.svg'
    'styles/custom_game/elysium_ability_buffs_v3.css'
    'layout/custom_game/elysium_ability_buffs_v3.xml'
)
foreach ($hudInput in $hudInputs) {
    & $resourceCompiler -i (Join-Path $hudSource $hudInput) -r
    if ($LASTEXITCODE -ne 0) { throw "Ошибка компиляции: $hudInput" }
}
```

Команды предполагают, что `elysium_dev` уже создан в Workshop Tools
Проверить итоговые файлы обязательно: успешная сборка плагина их не создаёт

| Исходник внутри addon | Результат внутри addon |
| --- | --- |
| `panorama/layout/custom_game/elysium_ability_buffs_v3.xml` | `panorama/layout/custom_game/elysium_ability_buffs_v3.vxml_c` |
| `panorama/styles/custom_game/elysium_ability_buffs_v3.css` | `panorama/styles/custom_game/elysium_ability_buffs_v3.vcss_c` |
| `panorama/images/custom_game/elysium/abilities/*.svg` | `panorama/images/custom_game/elysium/abilities/*.vsvg_c` |

Нужны все восемь иконок: `heal`, `leap`, `blind`, `charge`, `trap`, `catch`, `double_jump`, `generic`
SVG — векторные ресурсы VSVG, а не VTex
Не добавлять их в игровой список `PrecacheResources`: Panorama загружает изображения через XML
Иконки входят в исходники эксперимента; внешние изображения и шрифты не требуются
XML использует Panel, Image, Label и CSS, без клиентского JavaScript и захвата мыши

Имена layout и CSS получили суффикс `_v3`, чтобы старый VPK без стилей персонального размера и положения не проходил проверку новой версии плагина
При обновлении первой версии эксперимента нужно пересобрать addon, одной замены DLL недостаточно

## 3. Доставить и смонтировать addon

Для проверки через Workshop Tools можно запускать собственный dev-addon без публикации в Workshop
На отдельном сервере одного открытого клиентского dev-addon недостаточно: сервер также должен монтировать тот же скомпилированный набор в `GAME`
Способ загрузки локального addon зависит от используемого загрузчика; простое копирование VPK рядом с DLL его не подключает

Для обычного сервера включить всю скомпилированную папку `panorama/` в свой VPK и обновить addon у сервера и клиентов штатным способом
Внутри VPK пути начинаются с `panorama/`, без префиксов `content/`, `game/` и имени addon

Если используется [Source2ZE MultiAddonManager](https://github.com/Source2ZE/MultiAddonManager), добавить Workshop ID в существующий список `mm_extra_addons` в `game/csgo/cfg/multiaddonmanager/multiaddonmanager.cfg`
Сохранить уже подключённые ID; не заменять весь список одним HUD addon
`mm_client_extra_addons` подключает ресурсы только клиентам и для этого эксперимента недостаточен
После доставки обновления перезагрузить карту и переподключить клиентов
`mm_print_searchpaths` позволяет проверить монтирование на сервере
У другого AddonManager имена команд могут отличаться

Для [SwiftlyS2 AddonsManager](https://github.com/SwiftlyS2-Plugins/AddonsManager) ID добавляется строкой в существующий массив `Main.Addons` файла `addons/swiftlys2/configs/plugins/AddonsManager/config.jsonc`
Команды этого загрузчика: `sw_downloadaddon <workshop_id>` скачивает addon, `sw_searchpath` показывает смонтированные VPK
При ручном локальном тесте одинаковый комплект ресурсов должен быть установлен и смонтирован на обеих сторонах

Готового скомпилированного VPK в PR нет: CS2 Workshop Tools в среде разработки недоступны
Скопированные рядом с плагином исходные XML/CSS/SVG не заменяют скомпилированный клиентский addon

## 4. Включить и проверить

В серверной консоли или от администратора с правом `zombie_plague.admin.classes`:

```text
zp_ability_hud on
zp_ability_hud status
```

`on` ставит создание сущности на следующий игровой кадр
Повторить `status` после начала обновлений: ожидается `работает`, `api=True`, а у живого игрока с назначенными способностями — `recipients` больше нуля
Счётчик `players` из версии hud.3 переименован и дополнен диагностикой:

| Поле | Значение |
| --- | --- |
| `connected` | Подключённые реальные игроки SwiftlyS2, без ботов |
| `tracked` | Реальные игроки с зарегистрированной ролью ZombiePlague |
| `recipients` | Игроки с непустым последним кадром HUD на сервере, без скрытых панелей |
| `ticks` | Число успешно завершённых обновлений HUD после последнего включения |
| `last_tick_ms` | Время после последнего обновления; `never`, если обновлений ещё не было |

`recipients` не является подтверждением отображения панели клиентом
У мёртвого игрока, при обычном меню или отсутствии способностей он не увеличивается

В игровом чате администратор может вызвать `!zp_ability_hud on`, затем `!zp_ability_hud status`
Имена без `!` выше предназначены прежде всего для консоли процесса сервера

Если сервер работает, а панель не появляется, выполнить:

```text
zp_ability_hud debug
```

Команда в серверной консоли показывает всех подключённых реальных игроков, включая тех, для кого ещё не создана роль ZombiePlague
Вызов `!zp_ability_hud debug` из чата выводит подробности только о вызывающем игроке в его консоль игры `~`
Диагностика читает текущую роль, меню и способности без их активации, запросов в БД и принудительного включения HUD
Для каждой записи выводятся слот, SteamID, состояние жизни, роль, класс, число способностей, отсутствующие метаданные и ID способностей
У зомби `class` — ID класса каталога, у людей — тип текущего игрового класса
`eligible_icons` — число иконок, подходящих для отправки сейчас, `sent_icons` — число иконок последнего сохранённого сервером кадра
Также выводятся личные размер и положение панели

| `reason` | Что проверить |
| --- | --- |
| `MissingRole` | Роль ZombiePlague ещё не создана; проверить появление игрока после подключения или обновления плагина |
| `Dead` | Сервер считает игрока мёртвым |
| `MenuOpen` | Закрыть обычное меню; меню настройки HUD допускает предпросмотр |
| `NoAbilities` | В текущем экземпляре класса нет способностей; проверить назначения, включённость и сторону, после reload дождаться пересоздания роли |
| `MissingPresentation` | Способности есть, но отсутствуют метаданные HUD; проверить комплект DLL и создание роли после обновления |
| `Ready` | Набор готов на сервере; при `sent_icons > 0` проверить клиентскую загрузку и ошибки разбора Panorama |

Если `ticks` остаётся нулём через несколько секунд активной игры, диагностика ещё не подтверждает работу повторяющегося таймера
Если `ticks` растёт, а `recipients=0`, причины по игрокам объясняют, почему набор не попадает в панель

Перед запуском сервер проверяет наличие layout, CSS и всех восьми иконок v3 в смонтированной файловой системе `GAME`
При нехватке файлов `status` и лог содержат конкретные пути
Если сервер пишет `работает`, а панели нет, сначала проверить `debug`, затем наличие тех же ресурсов у клиента и ошибки загрузки Panorama в клиентской консоли
Серверная проверка не подтверждает наличие или успешный разбор ресурсов на клиенте

```text
zp_ability_hud off
```

Отключение отменяет таймер и удаляет сущность
После исправления ресурсов повторная попытка запускается через `on`
Команды не меняют конфиг на диске

## Автоматическое включение

В `configs/plugins/ZombiePlague.Core/ability_hud.json` относительно SwiftlyS2:

```json
{
  "AbilityHud": {
    "Enabled": true,
    "RefreshSeconds": 0.25,
    "ShowNames": true,
    "HideWhenMenuOpen": true
  }
}
```

Конфиг читается при загрузке плагина, автоматического отслеживания файла нет
`RefreshSeconds` допускает от 0.1 до 2 секунд
Для применения изменений перезагрузить плагин или сервер; включённый HUD пересоздаётся при смене карты
Личные размер и положение меняются через `!hud` без пересборки addon
Изменение самих стилей иконок или набора поддерживаемых позиций требует пересборки addon

## Проверка и нагрузка

Одна сущность `custom_hud_layout`, состояния персональны для каждого игрового слота
Обновление по игровым тикам раз в 0.25 секунды; HUD не делает запросов в БД
Повторно передаются только изменившиеся классы и подписи, число целевых панелей ограничено разметкой
Таймер отменяется, обработчики снимаются и сущность удаляется при выгрузке плагина

```powershell
dotnet test CS2ZombiePlague.sln --configuration Release --no-build --no-restore
```

Автотесты проверяют наборы людей/зомби/Survivor/Nemesis, личные и классовые выдачи, дедупликацию, отсутствие чужих и отключённых способностей, полный набор из 48 иконок, локализацию для разных игроков, КД активных и пассивных способностей, отправку только изменений, очистку слотов, смену роли соответствие XML серверным целям, персональные настройки и сохранение, сброс до ответа БД, очистку размеров/позиций при повторном входе, предпросмотр и EF-миграцию
Сборка C# и проверка XML не заменяют компиляцию Panorama и запуск внутри CS2

На тестовом сервере проверить два разных набора игроков, совпавшую личную и классовую выдачу, запуск/окончание КД, заражение, Survivor/Nemesis, смерть, меню, повторное подключение, `off`, смену карты и выгрузку плагина
Проверить `!hud` у двух игроков: разные размер/положение, предпросмотр, сброс и сохранение после переподключения
Размещение и читаемость панели на рабочих разрешениях остаются частью проверки в игре
