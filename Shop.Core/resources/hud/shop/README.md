# Магазин Elysium через Custom HUD

Это часть `Shop.Core 1.9.0`, отдельный серверный плагин не устанавливается

## Ресурсы V4

Магазин использует комплект `elysium_shop_v4_r7`, с той же допустимой структурой Panorama, что рабочие HUD способностей и сообщений Elysium V4
Суффикс `_v4` — обозначение ревизии ресурсов проекта; сам по себе он не переключает формат компилятора Valve
Совместимость обеспечивают содержимое XML/CSS и компиляция актуальными CS2 Workshop Tools

`r5` добавляет двухфазный скролл только изменяемой области, независимый цвет рамки при наведении, заметный отсчёт кулдауна и SVG шестерёнки из пользовательского пака `elysium-hud-icons-42.zip`. В кошельке остаётся только сумма; нижняя текстовая подсказка удалена. Общий размер, подтверждение покупки, персональный масштаб и защита от устаревших кликов сохранены
При переходе с предыдущего комплекта магазина нужно обновить `Shop.Core` и VPK вместе
Старые ресурсы не переименовывать: заново скомпилировать XML/CSS, чтобы в layout записалась правильная зависимость на stylesheet

При сборке аддона также импортируйте `content/panorama/images/custom_game/shop/gear.svg`.
Workshop Tools должны создать `game/panorama/images/custom_game/shop/gear.vsvg_c`; включите его в VPK вместе с layout/styles `r5`.

## Поведение

- `!weapons`, `!shop` и `!магазин` переключают HUD
- Пункт магазина в главном меню и `IShopApi.Open` открывают тот же HUD
- При открытии штатного закупа Shop сначала закрывает его командой `buymenu`, ждёт подтверждение закрытия и затем открывает свой HUD
- Крестик, команды магазина, B и Escape (когда его доставляет SwiftlyS2) запускают выбранную анимацию закрытия; до её завершения повторные покупки отклоняются. Принудительное закрытие при смерти/заражении/выгрузке освобождает курсор сразу
- Все цены, категории, локализованные названия, права, лимиты и кулдауны берутся из текущего снимка Shop
- В HUD попадают активные предложения Shop: зарегистрированные предметы `custom_equipment` обычное оружие `cs2_weapon` из поддерживаемого каталога CS2 и встроенная броня `builtin / armor`
- Фиксированного набора категорий или товаров нет: используются категории Shop, пустые скрываются; товары без категории остаются в общей колонке
- Стандартные пушки не обязаны быть зарегистрированы в CustomEquipment, но обязательно должны иметь активное предложение Shop; автоматически весь арсенал CS2 не добавляется
- Гранаты и кастомная экипировка берутся только из CustomEquipment; неизвестные предметы и встроенные товары кроме брони в HUD не добавляются
- Все подходящие товары текущей стороны доступны через страницы: до восьми категорий одновременно и шести карточек на категорию; ёмкость страницы задаётся в CMS
- Rarity берётся из зарегистрированного предмета; у обычного оружия и при отсутствии свойства используется Common
- Иконки остаются светлыми; цвет Rarity образует свечение вокруг силуэта, небольшой маркер и рамку карточки при наведении
- Размер окна статичен и задаётся в CMS: ширина, высота и масштаб по умолчанию общие для людей и зомби; пустой каталог и неполная страница не меняют геометрию
- Шестерёнка открывает настройку масштаба: 75, 85, 100, 115, 125%; выбор применяется сразу и сохраняется по SteamID в `shop.player_preferences`
- Чтение настройки выполняется один раз при подготовке HUD за подключение, запись — при выборе размера, асинхронно; каталог и баланс по-прежнему читаются из памяти
- Пока открыта панель настроек, покупка и перелистывание отключены; повторная шестерёнка закрывает настройки
- При ошибке БД выбранный масштаб действует до отключения, а в настройках появляется ошибка с предложением повторить выбор; неподтверждённая запись не считается сохранённой
- Название, иконка и цена находятся в отдельных строках; длинное название занимает до двух строк
- Кастомные пушки используют собственный VSVG, затем силуэт `InheritorName`; иконка оффера имеет приоритет над иконкой оружия
- Недоступная карточка серая, её Button скрыт; даже поддельный клик повторно проверяется на сервере
- При нехватке денег надпись «Недостаточно денег» не выводится — только серый цвет и отключённый клик
- Баланс и доступность обновляются каждые 0,25 секунды из памяти, без опроса БД, закрытия HUD или сброса выбранной страницы
- Покупка вызывает `ShopPurchaseService.TryPurchase`, включая возврат средств при ошибке выдачи
- Пока HUD открыт, закупка патронов через E заблокирована; курсор захватывается только у владельца
- HUD закрывается при смерти, переходе в наблюдатели, отключении, смене карты, выгрузке и после 60 секунд без действий
- При заражении, смерти и смене роли HUD закрывается и освобождает курсор; автоматически магазин другой стороны не открывается
- На время магазина скрываются штатные радар, прицел и выбор оружия через `CCSPlayerPawn.HideHUD`; при закрытии убираются только биты, добавленные Shop
- При смене сущности игрока восстановление старого состояния не затрагивает новый pawn: сохранённый handle проверяет serial
- При отсутствии ресурсов доступен обычный магазин `!shop_classic`, захват мыши не включается

## B, CSS-триггер и закрытие CS2

Требуется клиент/сервер с обновлением Valve от 9 сентября 2026:
`HUD_BUYMENU_VISIBLE` приходит в верхний уровень Custom HUD от клиента,
а `custom_hud_layout` рисуется поверх базового HUD.

Магазин заранее готовит персональную сущность для каждого живого игрока доступной
стороны. Подготовка не открывает окно, не захватывает мышь и не блокирует E.
Класс `NativeBuyTrigger` назначается только владельцу этой сущности, поэтому
открытие B не показывает чужие копии магазина.

```css
.ShopRoot { visibility: collapse; }
.HUD_BUYMENU_VISIBLE .ShopRoot.NativeBuyTrigger {
    visibility: visible;
    background-color: #050b12;
}
.ShopRoot.Visible { visibility: visible; }
```

1. B открывает CS2 buymenu, и клиентский CSS сразу показывает готовый Shop поверх него
2. Сервер закрепляет персональный `Visible`, включает ввод Shop и отправляет одну `buymenu` для закрытия CS2
3. После закрытия CS2 класс `HUD_BUYMENU_VISIBLE` исчезает, но `Visible` сохраняет наш магазин
4. Следующее открытие CS2 по B закрывает оба меню; крестик, Escape и `!weapons` также закрывают Shop

Подписки на `OnTick`, отмены `buymenu_open`, ожидания подтверждения перед показом
и прежних двухсекундных таймаутов больше нет. Уже существующий служебный таймер
раз в 50 мс обнаруживает серверный флаг для закрепления показа и закрытия CS2,
обслуживает ввод/анимации; данные каталога обновляются отдельно раз в 0,25 с
по умолчанию. Первая видимость подготовленного оверлея определяется CSS, а не
моментом серверной проверки. CSS сам не отправляет команды и не хранит состояние
после удаления класса Valve, поэтому оставшийся серверный переход необходим.

Фон непрозрачен на весь экран, пока CS2 buymenu видимо: края штатного меню не
просвечивают при любом масштабе магазина и во время анимации окна. После закрытия
CS2 возвращается обычный фон Shop. Анимация открытия имеет одинаковое имя до/после
закрепления `Visible`, чтобы изменение селектора не запускало её повторно.

`buymenu` пропускается перехватчиком команд. `buy`, `buyrandom`, `autobuy`, `rebuy`,
дошедшие до сервера, по-прежнему блокируются при включённой замене. Shop выдаёт
предметы через собственный сервис и экономику.

Escape отменяет ещё не обработанный триггер без переключающей команды —
запоздалый сетевой флаг не должен повторно открыть закрытый клиентом закуп.
Смерть, смена стороны, наблюдение, отключение и выгрузка освобождают ввод и удаляют
старую сущность. Новая сторона не открывается автоматически из прежнего состояния B.

`shop_hud` показывает `mode=css_trigger`, количество подготовленных/открытых HUD,
счётчики `native_triggers` и `native_close_requests`. `shop_hud reload` повторяет
подготовку после исправления ресурсов. Старый `shop_hud trace` удалён вместе с
прежним перехватом.

Если карта/настройки не позволяют клиенту открыть CS2 buymenu, класс не появится.
В ZombiePlague `MapService` удаляет `func_buyzone`; доступны `!weapons`, `!shop`
или добровольный `bind b weapons`. Плагин не меняет бинды игрока.

Компиляция ресурсов Workshop Tools и игровой тест обязательны: нужно проверить
порядок доставки `Visible` и команды закрытия, сохранение фокуса, быстрое B/Escape,
клики и задержку сети. Проверки исходников и браузера не доказывают отсутствие
единственного кадра штатного окна во всех состояниях клиента.

Источник: [обновления Valve](https://store.steampowered.com/oldnews/?appgroupname=Counter-Strike:+Global+Offensive&appids=730&feed=steam_community_announcements)

## Установка

1. Собрать ветку обычной командой репозитория

   ```powershell
   pwsh ./scripts/build-package.ps1 -Configuration Release
   ```

2. Обновить папку `Shop.Core` из `dist/Release/plugins` целиком
   Обновить `Localization.Core` из того же runtime, чтобы добавить ключи `Shop.Hud.*` в БД и fallback

3. Скопировать содержимое `Shop.Core/resources/hud/shop/content` в content-каталог своего аддона

   ```text
   .../Counter-Strike Global Offensive/content/csgo_addons/<addon>/panorama/
   ```

4. Открыть аддон в CS2 Workshop Tools и скомпилировать новые XML/CSS через Asset Browser
   В VPK должны попасть

   ```text
   panorama/layout/custom_game/elysium_shop_v4_r7.vxml_c
   panorama/styles/custom_game/elysium_shop_v4_r7.vcss_c
   panorama/styles/custom_game/elysium_equipment_icons_v4.vcss_c
   ```

   Штатные SVG оружия уже входят в CS2. Для собственных иконок распаковать
   экспорт ElysiumShop поверх исходников, скомпилировать SVG и CSS иконок.
   Даже без собственных иконок пустой `elysium_equipment_icons_v4.css` должен быть скомпилирован
   Исходные XML/CSS не заменяют скомпилированные ресурсы

5. Доставить обновлённый VPK серверу и клиентам, затем сменить карту или перезапустить сервер
6. В консоли сервера выполнить `shop_hud`; ожидается `enabled=True`, `replace_buy=True`, `error=-`
7. В игре выполнить `!weapons`; для повторной попытки после исправления VPK — `shop_hud reload`

## Оформление из Web

ElysiumShop 1.3.0 сохраняет `shop.storefronts.hud_settings`; fallback содержит
`hudSettingsJson`. Старые файлы используют значения по умолчанию. Применение —
`shop_reload` или обновление каталога в конце карты.

Ширина (960–1720 px), высота (640–980 px) и масштаб по умолчанию общие для двух
витрин. CMS сохраняет их обеим сторонам одной транзакцией; при разном внешнем
fallback сервер берёт геометрию витрины людей. Личный масштаб игрока действует
поверх этого правила; пока игрок не выбирал масштаб, используется серверный.
Число товаров/категорий и переход между сторонами размер окна не меняют.

Остальное настраивается отдельно: три дизайна, пять акцентов, появление и закрытие
(none/fade/slide/zoom), выбор (none/pulse/lift), страницы (none/fade/slide),
скорость, подсветка, вид иконок, имена, ёмкость 1–8 × 1–6, циклическое листание.
Клик либо покупает и оставляет окно, либо покупает и закрывает, либо выбирает
товар с отдельным подтверждением. Устаревшая кнопка другой страницы/выбора
не покупает новый товар. Лимит всей витрины за раунд считает успешные покупки
отдельно для каждой стороны и дополняет лимиты оффера; 0 отключает ограничение.

XML и CSS игрового окна служат источником Web-превью. Генератор создаёт дерево
панелей, CSS для браузера и контрольную сумму исходников. Для синхронизации:

```bash
python scripts/generate-shop-hud.py --cms-assets /path/to/website-flute-cms/app/Modules/ElysiumShop/Resources/assets
```

Версионируются все три Web-файла: `hud-appearance.json`, `shop-hud-template.json`,
`shop-hud.css`. Тест проверяет контрольную сумму против текущего XML/CSS.
Браузер переводит свойства Panorama в CSS; фактическую компиляцию и визуальное
совпадение с клиентом нужно проверить в актуальных Workshop Tools/CS2.

Оффер может задать `settings.hud_icon`: `auto`, имя штатной иконки или путь
загруженного VSVG. Затем используется `IHasHudIcon.HudIconPath`, затем
`InheritorName`. Отсутствующий ресурс в GAME приводит к базовой иконке.
`EquipmentHudIcon.Resolve` доступен другим Custom HUD. Архив CMS содержит
иконки оружия и назначенные иконки офферов обеих сторон. После новых назначений
обновить CSS/VPK; после изменений только оформления компиляция не нужна.

Броня `builtin / armor` входит в HUD; успешная покупка добавляет настроенное
количество до 100. При полной броне неудачная выдача возвращает платёж и
не расходует лимит. Инспектор Web сохраняет имя, иконку, цену, лимиты и cooldown
одной транзакцией с оформлением, сохраняя остальные параметры оффера.

## Настройки

При первом запуске создаётся `cfg/Shop.Core/shop_hud.json` в дереве конфигурации SwiftlyS2
Настройки отделены от экспортируемого сайтом `shop.json` и применяются после перезагрузки плагина

```json
{
  "ShopHud": {
    "Enabled": true,
    "ReplaceNativeBuyMenu": true,
    "HideNativeHudWhileOpen": true,
    "RefreshIntervalSeconds": 0.25,
    "IdleTimeoutSeconds": 60
  }
}
```

`Enabled=false` возвращает стандартный серверный Shop по командам, а перехват нативной закупки отключается
`ReplaceNativeBuyMenu=false` оставляет HUD по `!weapons`/`!shop`, без замены B и блокировки штатных команд закупки
`HideNativeHudWhileOpen=false` отключает временное скрытие штатного радара, прицела и выбора оружия

## Проверка в игре

1. Два игрока одновременно открывают HUD с разными балансами — каждый видит свою доступность
2. B → наш HUD; убедиться, что CS2 buymenu закрылось, а Shop остался открытым → повторное B → закрыто; затем проверить крестик, `!weapons`, быстрый Escape до серверного закрепления и задержку сети
3. Купить оружие и гранату из CustomEquipment — один клик вызывает одну покупку и сразу обновляет баланс; изменить баланс извне — карточки обновляются без закрытия и сброса страницы, при нехватке денег текстовая причина не появляется
4. Нажать недоступную карточку и повторить покупку после исчерпания лимита — списания и выдачи нет
5. Листать товары и категории — предметы не пропадают после шестого товара или восьмой категории
6. Заразить игрока с открытым меню — HUD закрывается; смерть/наблюдение также закрывают HUD и освобождают мышь; магазин зомби открывается только новым действием игрока
7. Перезагрузить Shop, сменить карту и переподключить игрока — старый HUD и захват мыши не остаются
8. Проверить E, способности и стрельбу при захваченном курсоре; до первого B подготовленный скрытый HUD не должен блокировать управление
9. Проверить обычные пушки из Shop: все включённые предложения присутствуют в своих категориях, Rarity Common, покупка выдаёт выбранное оружие
10. Проверить радар до открытия, в магазине и после закрытия/смерти/заражения; другие настройки скрытия HUD должны сохраниться
11. Проверить 1, 3 и 8 категорий, длинные названия, полный ряд и последнюю страницу на 16:9 и 4:3
12. Выбрать каждый масштаб, проверить попадание мыши в карточки, края окна и настройки на 16:9 и 4:3; переподключиться — масштаб восстановлен
13. Быстро листать и нажимать карточку предыдущей страницы — неверной покупки нет, окно не исчезает
14. При медленной БД выбрать размер до окончания загрузки — старый ответ не меняет выбор; при ошибке записи повторить выбор после восстановления БД

## Изменение макета

Редактировать `scripts/generate-shop-hud.py`, затем выполнить `python scripts/generate-shop-hud.py`
Генератор читает размеры пула из `ShopHudCatalog`, масштабы из `ShopHudPreferences`, имена ресурсов из `ShopHudRuntime`; значения не дублируются отдельно в Python
Свечение — отдельный размытый фон под светлым силуэтом; `img-shadow` не используется для фонового Panel, поскольку предназначен для Image
Макет не содержит JS, onactivate, snippets или неподдерживаемых атрибутов
Корневая панель `ShopViewport` не имеет `id`: компилятор Panorama запрещает его на корне
Адресуемая сервером панель `ShopRoot` расположена внутри неё; не переносить её `id` на корень
Кнопки недоступных товаров скрываются CSS, поскольку атрибут `enabled` не входит в допустимый формат Custom HUD
Переключение страниц, баланса и масштаба сохраняет сущность, не вызывает Despawn/Spawn и не освобождает курсор
ID кнопок покупки и навигации чередуются между наборами A/B; запоздалые клики предыдущего набора отклоняются
Если сами товары или цены заменены извне (shop_reload, удаление регистрации), сущность заменяется для отбрасывания кликов старого каталога; повторная загрузка идентичного каталога этого не вызывает
Снимок каталога и права покупки повторно проверяются перед обработкой клика
