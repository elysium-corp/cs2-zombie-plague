# Shop.Core

`Shop.Core` отделяет игровую экономику от каталога `CustomEquipment`.
Оружие, гранаты и предметы регистрирует модуль экипировки, а цены,
платные патроны, категории, лимиты, cooldown и права принадлежат магазину.

## Данные магазина

Миграция создаёт отдельную схему PostgreSQL `shop`:

- `storefronts` — настройки витрин `human` и `zombie`, включая режим сортировки;
- `categories` — необязательные категории витрины;
- `offers` — товар, цена, платные патроны, лимиты и cooldown;
- `offer_privileges` — привилегии товара для режимов `any` и `all`;
- `fallback_state` — единственный флаг `dirty`, без номера ревизии.

У оффера `category_id = null` означает размещение непосредственно в корне
магазина. Нулевые `max_purchases_per_round`, `max_purchases_per_map` и
`cooldown_seconds` отключают соответствующее ограничение. `ammo_price = null`
отключает докупку патронов, а `ammo_amount` задаёт число патронов за одно
нажатие `E`.

`access_mode` принимает следующие значения:

- `everyone` — список привилегий должен быть пустым;
- `any` — достаточно одной привилегии из списка;
- `all` — нужны все привилегии из списка.

`sort_mode` задаётся отдельно для каждой витрины: `priority`, `price` или
`alphabetical`. Приоритет хранится в `sort_order`, алфавитная сортировка
использует локализованное название товара.

Любое изменение таблиц каталога триггером переводит `fallback_state.dirty` в
`true`. После успешного скачивания актуального fallback сайт должен установить
его в `false`; следующая правка снова вернёт `true`.

При обновлении существующей установки первая миграция один раз переносит
старые позиции из `custom_equipment.shop_*`. Исторические таблицы не
используются игровым runtime после переноса.

## Memory snapshot и fallback

При старте и в конце карты модуль сначала читает PostgreSQL. Если база или
снимок недоступны, загружается fallback:

```text
(swRoot)/configs/plugins/Shop.Core/shop.json
```

Готовый `shop.json` скачивается в админке `ElysiumShop`. Во время игры
категории и офферы читаются только из атомарно заменяемого memory snapshot;
открытие меню и покупка не выполняют SQL-запросы.

Fallback имеет `schemaVersion = 1`, дату `generatedAt`, обе витрины и массивы
`categories`/`offers`. Поле `settingsJson` оффера содержит JSON-объект строкой;
для встроенной брони поддерживается `armor_amount` от 1 до 100. Изменение файла
само по себе не меняет активный snapshot: он применяется только в конце карты
или командой `shop_reload`.

## Команды и игровое поведение

Команды администра:

- `shop_reload` — немедленно пересобрать snapshot;
- `shop_status` — показать источник, число категорий/офферов и время загрузки.

Игрок открывает магазин командой `!shop` (или из главного меню). Витрина
меняется между людьми и зомби автоматически. Платные патроны для активного
пользовательского оружия покупаются кнопкой `E`.

Начиная с 1.1.0, баланс не выводится в заголовках магазина и категорий.
Доступные товары с редкостью получают её цвет из каталога экипировки;
недоступные позиции остаются серыми. Обновление доступности при изменении
баланса сохраняется.

При открытом меню докупка патронов и активные способности заблокированы.
Покупка патронов не пишет в чат, в том числе при полном боезапасе или нехватке
денег. События магазина и серверные сообщения об ошибках выдачи/возврата
сохраняются. Для блокировки способностей вместе с Shop.Core необходимо
обновить ZombiePlague.Core.
