# Баннеры игровых плагинов

`Advertisement.Core 3.0.0` предоставляет `IBannerNotificationApi` из `CustomHud.Api`. Игровой плагин публикует событие и его данные, а выбранная серверная БД определяет текст, шаблон, позицию и порядок показа. Для прямого показа своего дизайна остаются `ICustomBannerApi` и `ICustomHudApi` из `CustomHud.Core 1.2.0`.

## Настройка в CMS

Откройте **Реклама → Баннеры**, выберите подключение игрового сервера и нажмите **Открыть**. Вкладка **Конструктор** содержит шаблоны, а **Плагины** — события каждого плагина. Выберите событие и назначьте шаблон, ключи Localization для используемых блоков, позицию и длительность. Изменение общего шаблона действует на все его привязки; кнопка создания копии позволяет оформить отдельное событие независимо.

В конструкторе доступны 12 готовых основ и вариант `custom` с независимыми Header, Title, Description. Настраиваются ширина, поля, промежутки, размер и цвет каждого текстового блока, фон и его непрозрачность, граница, углы, тень, иконка и её размер, эффекты появления/исчезновения, движение иконки, sound event и громкость. Поддерживаются история изменений, импорт/экспорт JSON, Preview в 16:9 / 4:3 / 21:9, редактирование тестовых значений параметров и библиотека параметров.

Текст берётся из общей Localization. Ссылка возле блока открывает нужный ключ для выбранного сервера. Используйте `<font color='#85dcb1'>цвет</font>`, `<b>`, `<i>`, `<u>`, `<br>` и `span style='color: …'`. Цвет конкретного HTML-фрагмента имеет приоритет над цветом блока. Цветовые теги чата `{accent}…{/accent}` не подходят для баннера. Имена игроков и другие строковые параметры экранируются до подстановки; числа и boolean сохраняют тип.

Каждому событию можно задать:

| Настройка | Значения |
| --- | --- |
| Включено | Отключает уведомление, игровое действие остаётся доступным |
| Позиция | Девять областей; сверху по центру — под списком игроков |
| Длительность | 0,5–60 секунд, затем эффект исчезновения |
| Доставка | `queue` — по очереди; `replace` — обновляет одно и то же событие |
| Приоритет | 0–1000; более высокий прерывает менее важное уведомление в той же области |
| Интервал | 0–300 секунд между принятыми уведомлениями одного события для игрока |
| Срок ожидания | 1–120 секунд; просроченное уведомление удаляется |
| Аудитория | Все, живые, мёртвые, люди, зомби, наблюдатели |
| Минимум игроков | 0–128, реальные авторизованные игроки |
| Параметры вручную | До 64 строк, чисел или boolean; автоматические значения не переопределяются |

В разных областях сообщения видны одновременно. В каждой области показывается одно уведомление; очередь ограничена 32 ожидающими сообщениями на игрока. Контекст фиксируется в момент события, поэтому отложенный баннер сохраняет исходный номер раунда и героя события. Обновления `replace` не повторяют входную анимацию и звук. Меню и HUD способностей используют отдельные сущности и продолжают отображаться.

## HUD способностей

**Плагины → ZombiePlague → HUD способностей** управляет постоянным виджетом: показ, названия, стандартная позиция, масштаб 50/75/100%, разрешение личных настроек. `top_left` находится под радаром (верхний отступ 320 единиц Panorama). Индивидуальный размер и safe-zone радара могут потребовать выбора другой позиции.

Отдельные всплывающие сообщения о перезарядке способности удалены. Таймер остаётся в HUD. Команда `hud` / `zp_hud` открывает личные настройки; сброс применяет текущие стандарты сервера. Существующие сохранённые настройки игроков миграция сохраняет; новые игроки получают серверные значения. При запрете личных настроек используются стандарты сервера, а сохранённый выбор игрока остаётся в БД.

## Параметры

Ключи регистронезависимы. `{player}` — получатель, кроме событий, где героем становится выбранный игрок или лидер рейтинга; `{recipient}` всегда обозначает получателя. Алиасы `{roundName}` и `{player_name}` разрешаются после данных события. Параметры конкретного события отображаются в его редакторе. Контекст ZombiePlague/Economy доступен при загруженном соответствующем плагине; при отсутствии обязательного значения Localization отклоняет отправку. Эти же общие параметры доступны рекламе; параметры отдельных событий реклама заполняет вручную.

## API и жизненный цикл

```csharp
interfaces.TryGetSharedInterface<IBannerNotificationApi>(
    IBannerNotificationApi.SharedApiKey, out var notifications);

notifications?.Publish(player, "Shop.Errors.NotEnoughMoney", new Dictionary<string, object?>
{
    ["product"] = localizedProductName, ["product_id"] = productId, ["price"] = price
});

// Собственный контекст хранится только пока загружен его владелец.
var registration = notifications?.RegisterContext("MyPlugin", player =>
    new Dictionary<string, object?> { ["season"] = 4 });
// При выгрузке:
registration?.Dispose();
```

Все операции API вызываются на игровом потоке. Для асинхронной работы вернитесь через scheduler, заново получите игрока и проверьте SteamID. `Publish` возвращает факт приёма события в очередь, не подтверждение отрисовки клиентом. `Clear(eventKey)` удаляет ожидающие и видимые экземпляры события. `RegisterContext` расширяет runtime-контекст; чтобы новый параметр появился в CMS, добавьте его в общий каталог.

Встроенные ключи событий находятся в `CustomHud.Api/Resources/notification-catalog.json`. Копия этого файла входит в модуль CMS. Для нового вида управляемого события добавьте метаданные, значения по умолчанию и миграцию правил/Localization в оба репозитория. Произвольный незарегистрированный `eventKey` не отправляется. Плагин может показывать произвольный баннер через `ICustomBannerApi` без регистрации события.

## Обновление и fallback

1. Установите полный согласованный runtime-пакет: Localization.Core 1.6.0, Advertisement.Core 3.0.0, CustomHud.Core 1.2.0, ZombiePlague.Core 0.6.0 и обновлённые потребители API.
2. Localization применяет `20260908100000_AddNotificationLocalization`, Advertisement — `20260908101000_AddNotificationRules`, ZombiePlague — `20260908102000_AddHudCustomizationFlag`. Advertisement ожидает ключи Localization; если первый запуск попал до окончания её миграции, после завершения выполните `ads_reload`.
3. Пересоберите и доставьте VPK сообщений **и способностей v4** из новых исходников Panorama. Суффикс v4 не изменился; старые скомпилированные файлы не содержат новых классов оформления и отступа под радаром.
4. Обновите ElysiumAdvertisements CMS до 3.0.0. Изменения правил/дизайна/виджета применяются при запуске, смене карты или `ads_reload`; тексты обновляются через обычную перезагрузку Localization.
5. Проверьте в CS2 меню вместе с HUD, стандартный/личный HUD, баннеры в выбранных позициях, иконки и звук. Браузерный Preview проверяет разметку и геометрию, но не заменяет игровой клиент.

Экспорт `advertisement.json` включает `Notifications` (правила с вложенными Template, Content, Options, Parameters) и `Widgets`. Переводы остаются в отдельном `localization.json`. При недоступной БД используется текущий снимок; до первой загрузки работают встроенные правила и локальный fallback. Уведомления не перенаправляются в чат при отсутствии Custom HUD. InfoNotify сохраняет существующие расписания и списки, передавая исходный текст как параметр `{message}` в настраиваемый баннер.

Меню, явно выбранные чатовые объявления и ответы диагностических команд не заменяются игровыми всплывающими уведомлениями. Миграции сохраняют исходные ключи Localization. При откате сначала назначьте описание объявлениям, использующим только Header/Title; ограничение БД защищает от несовместимого отката.
