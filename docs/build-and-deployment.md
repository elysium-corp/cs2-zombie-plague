# Сборка и развёртывание

Проект компилируется как модульное решение, но на сервер устанавливается только минимальный runtime. Игровая архитектура сохраняется: каждый плагин остаётся отдельной папкой SwiftlyS2, публичные `*.Api` размещаются в `resources/exports` ровно один раз, а `Common.Database` и его EF/Npgsql-зависимости остаются приватными для использующих их плагинов.

## Требования

- .NET SDK 10;
- PowerShell 7 (`pwsh`);
- Git для записи commit SHA в манифест.

## Полная сборка

Из корня репозитория выполните:

```powershell
pwsh ./scripts/build-package.ps1 -Configuration Release
```

Команда последовательно очищает только generated output, один раз восстанавливает NuGet-зависимости, один раз собирает solution, формирует runtime и проверяет его политику.

```text
dist/Release/
├── plugins/
│   ├── Admin.Core/
│   ├── Menu.Core/
│   ├── ZombiePlague.Core/
│   └── ...
├── packages/
│   ├── Admin.Core.zip
│   ├── ZombiePlague.Core.zip
│   ├── Elysium.Runtime.Release.zip
│   └── ...
└── runtime-manifest.json
```

- `plugins/` — единственные папки, которые следует копировать в `(swRoot)/plugins/`;
- `packages/` — архивы для GitHub, доставки и отката;
- `runtime-manifest.json` — список каждого файла, размер и SHA-256;
- `artifacts/` — промежуточный output компилятора, он не предназначен для сервера.

Полный архив содержит каталог `plugins/` и манифест. Отдельные ZIP удобны для точечного обновления одного модуля.

## Что исключается

Правила находятся в `eng/runtime-package-policy.json`. Из Release-runtime исключаются и дополнительно запрещаются проверкой:

- `SwiftlyS2.CS2.dll` и его runtime-граф — SDK уже предоставляет серверный хост;
- EF Core Design, Roslyn и satellite assemblies — они нужны для сборки и миграций, но не для игры;
- зависимости CLI/плагинной загрузки SwiftlyS2, не используемые игровым кодом проекта;
- native assets Windows, macOS, ARM и musl при целевой среде `linux-x64`;
- PDB и тестовые assemblies.

Упаковка завершается ошибкой, если отсутствует entry assembly, обязательная зависимость базы данных, API/export находится не в своём host-плагине, превышен лимит размера или количества файлов.

## Быстрая сборка изменений

Сначала хотя бы один раз создайте полный runtime. Затем можно собирать затронутые проекты:

```powershell
pwsh ./scripts/build-affected.ps1 -Configuration Debug -BaseRef origin/develop
```

Скрипт вычисляет изменённые проекты и их потребителей, выполняет один restore, собирает только нужные плагины с `--no-restore` и обновляет соответствующие папки/ZIP поверх полного baseline.

Изменение `Directory.Build.*`, solution, скриптов сборки или runtime policy автоматически переключает сборку на все проекты.

## Установка на сервер

1. Распакуйте `Elysium.Runtime.Release.zip` во временный каталог, не поверх работающего сервера.
2. Сверьте `runtime-manifest.json` и убедитесь, что внутри присутствуют ожидаемые папки плагинов.
3. Остановите игровой сервер или штатно выгрузите все обновляемые плагины.
4. Сделайте резервную копию только заменяемых каталогов `(swRoot)/plugins/<PluginName>`.
5. Замените эти каталоги одноимёнными папками из `plugins/`.
6. Запустите сервер и проверьте загрузку SwiftlyS2, регистрацию exports, подключение БД и начало раунда.

Не применяйте `rsync --delete` ко всему `(swRoot)/plugins`: там могут находиться сторонние плагины, которых нет в этом репозитории.

Конфигурации и пользовательские данные находятся вне runtime-папок — в `(swRoot)/configs/plugins/` и `(swRoot)/data/`. Сборка их не создаёт, не архивирует и не перезаписывает, поэтому рабочие настройки и права записи сохраняются.

## Откат

Если проверка после запуска не прошла:

1. остановите сервер;
2. верните сохранённые папки плагинов целиком;
3. не откатывайте `configs/plugins` и `data`, если формат данных не менялся;
4. снова запустите сервер и сохраните журналы неудачной версии для диагностики.

Для воспроизводимого отката храните полный ZIP, `runtime-manifest.json` и commit SHA одной версии вместе. Миграции базы данных выполняются отдельно и не входят в обычную Release-сборку.
