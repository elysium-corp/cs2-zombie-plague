# Выбор ножа Elysium через Custom HUD

Команды `!knife`, `!zknife`, `!нож` и пункт главного меню открывают персональное
меню с мышью. Строка выбирает предпросмотр, нижняя кнопка подтверждает выбор.
Крестик, повторная команда и Escape закрывают окно. Шестерёнка меняет масштаб
75/85/100/115/125%; личное значение хранится до отключения игрока.

Меню доступно людям и зомби из CT/T, включая мёртвых игроков. Зомби сохраняет
**предпочтение для человека**: модель, скорость, гравитация, урон и отбрасывание
человеческого ножа ему не применяются. Сохранённый нож выдаётся при первом
переходе в живого человека: через Humanized, Disinfected, RoleApplied,
BecameSurvivor или spawn.
Переход без возрождения также поддерживается. Выбор использует существующее
хранилище предпочтений и сохраняется в БД при штатном сохранении/отключении.
Перед выдачей снова проверяются роль, команда, pawn, сессия и доступ к ножу.
Если право отозвано или нож удалён, действует существующий fallback каталога.

Смерть, смена роли/команды/карты, отключение и выгрузка закрывают окно и
освобождают мышь. После заражения меню можно открыть заново. При конфликте
с другим захватывающим ввод HUD меню ножей закрывается.

## Оформление

Окно 1720×980 в координатах Panorama высотой 1080, с ограничением по экрану:
тёмные плоские панели, тонкие серые рамки, золотое выделение, шапка ELYSIUM
с подзаголовком как в предоставленном магазине. В списке семь строк на страницу,
SVG-силуэты и состояния выбора; справа PNG-превью, характеристики и описание.
Описание занимает всю оставшуюся часть нижнего контейнера и прокручивается.
Раритетность не отображается.

Правая колонка делится поровну между превью и подробностями. В подробностях
характеристики занимают 43%, описание — оставшиеся 57%; зазор входит во внутренний
отступ колонки описания. Строки характеристик имеют постоянную высоту: название
сверху, текущее значение → выбранное значение и разница снизу. Если при увеличении
масштаба четыре строки не помещаются, список прокручивается колесом мыши,
сохраняя высоту строк. Заголовок и подсказка сравнения остаются на месте.

Характеристики берутся из настоящего каталога: скорость, множитель урона,
гравитация и сила отбрасывания. Слева — сохранённый человеческий нож, справа —
предпросмотр. Числовое увеличение зелёное, уменьшение красное, равенство серое;
это относится и к гравитации. При текущем значении 0 выводится абсолютная разница,
поскольку процент относительно нуля не определён. После подтверждения новый нож
становится базой сравнения. Параметры класса зомби в сравнении не участвуют.

Используются нативные `Panel`, `Label`, `Button`, `flow-children`,
`fill-parent-flow`, `gradient`, `ui-scale`, `visibility: collapse`.
`_v4` — ревизия Elysium, а не версия синтаксиса или компилятора Valve.
Внешняя панель не имеет `id`; вложенные `id` необходимы серверу для обновлений
и кликов. У `Label` недопустим атрибут `html`, даже со значением `false`.
JavaScript, DOM и браузерные CSS-свойства в игровых ресурсах не используются.

Пиксельное совпадение и нативная компиляция должны быть проверены в CS2 Workshop
Tools и игре. .NET-тесты и статическая проверка XML/CSS этого не заменяют.
Фоном служит текущая игровая сцена под затемнением. Реальный каталог сервера
может отличаться от иллюстративного набора ножей согласованного макета.

## Сборка и установка

1. В актуальных CS2 Workshop Tools создайте addon `elysiumhud`.
2. Из корня репозитория выполните:

```powershell
python scripts/generate-knife-hud.py --check
pwsh scripts/compile-knife-hud.ps1 `
  -Cs2Path 'C:\Program Files (x86)\Steam\steamapps\common\Counter-Strike Global Offensive' `
  -Addon elysiumhud
```

Скрипт копирует только ресурсы Knife HUD; затем компилирует изображения, CSS
и XML. Ресурсы магазина он не заменяет. В VPK должны войти:

```text
panorama/layout/custom_game/elysium_knife_selector_v4.vxml_c
panorama/styles/custom_game/elysium_knife_selector_v4.vcss_c
panorama/styles/custom_game/elysium_knife_images_v4.vcss_c
panorama/images/custom_game/elysium/knives/gear.vsvg_c
```

А также все собственные изображения, указанные в manifest. Штатные иконки
и PNG-превью входят в CS2 и не требуют копирования в addon.

3. Обновите `CustomKnife.Core` и `Localization.Core` из одной сборки, пересоберите
и доставьте VPK серверу и клиентам. Правка XML/CSS или обновление DLL без VPK
не меняют уже скомпилированное меню. При прежней ошибке `disallowed attribute html`
нужно заменить именно заново скомпилированный `_v4.vxml_c`.
4. Проверьте открытие в игре, отсутствие ошибок Custom HUD и освобождение курсора.

## SVG списка и PNG предпросмотра

В `knife-hud-assets.json` две независимые группы: `icons` принимает только `.vsvg`,
`previews` — только `_png.vtex`. Генератор создаёт отдельные классы и серверные
списки допустимых ключей; неизвестный ключ использует `knife` соответствующей
группы. URL, произвольные классы и подстановка PNG вместо SVG не допускаются.

В комплекте есть штатные Knife, Karambit, M9 Bayonet, Butterfly, Huntsman,
Falchion, Skeleton и Shadow Daggers. Если `internal_name` совпадает с ключом
или имеет префикс `knife_`, соответствующая картинка выбирается автоматически.
Для собственных Axe/Spike/Piercer/Katana нужны изображения их моделей; пока
они не назначены, показывается стандартный нож. Это не скриншоты пользовательских
моделей и не скины из макета. HTTP-поле `image_url` сайта не загружается клиентом
Custom HUD автоматически.

Например, для `knife_katana`:

1. Добавьте `katana.svg` и прозрачный `katana.png` в
`content/panorama/images/custom_game/elysium/knives/`.
2. Дополните обе группы manifest, сохранив существующие записи:

```json
{
  "icons": {
    "knife": "s2r://panorama/images/icons/equipment/knife.vsvg",
    "katana": "s2r://panorama/images/custom_game/elysium/knives/katana.vsvg"
  },
  "previews": {
    "knife": "s2r://panorama/images/econ/weapons/base_weapons/weapon_knife_png.vtex",
    "katana": "s2r://panorama/images/custom_game/elysium/knives/katana_png.vtex"
  }
}
```

3. Запустите `python scripts/generate-knife-hud.py`, пересоберите плагин и VPK.
`katana.vsvg_c` и `katana_png.vtex_c` должны попасть в VPK.
4. При необходимости переопределите автоматическое сопоставление в конфигурации
`knife-hud.json` плагина CustomKnife.Core:

```json
{
  "KnifeHud": {
    "RefreshIntervalSeconds": 0.25,
    "IdleTimeoutSeconds": 120,
    "DefaultScale": 100,
    "Knives": {
      "knife_katana": {
        "Icon": "katana",
        "Preview": "katana",
        "SubtitleKey": "CustomKnife.Katana.Subtitle"
      }
    }
  }
}
```

`Image` старого конфига поддерживается как запасное имя `Preview`; на SVG списка
оно не влияет. Старые `Rarity` и `BenefitKeys` больше не используются. Имя,
описание и характеристики берутся из каталога; без `SubtitleKey` в подзаголовке
предпросмотра используется описание. Новые подписи доступны для ru/en/de/pl
через добавочную миграцию Localization.Core без перезаписи пользовательских
переводов. Конфиг оформления не меняет баланс или права на ножи.

## Магазин и пропавшие иконки

Knife HUD использует собственные пути и CSS-классы с префиксом `Knife`.
Для Shop собственные назначения иконок из CMS требуют экспортированного
`elysium_equipment_icons_v4.css` и соответствующих VSVG в VPK. В репозитории
этот CSS — заглушка; если скопировать её поверх экспорта, назначения исчезнут.
Иконка брони при этом может сохраниться, поскольку использует штатный ресурс.

Для проверки восстановите актуальный экспорт ElysiumShop **поверх** исходников
Shop, пересоберите изображения/CSS/XML и проверьте `shop_hud` на сервере.
Без установленного VPK и лога компиляции это возможная причина, а не подтверждённый
диагноз. Конфигурация оформления Shop хранится отдельно в `hud_settings`.

## Проверки

```bash
python3 scripts/generate-knife-hud.py --check
python3 -m unittest discover -s scripts/tests -p 'test_knife_hud_resources.py' -v
dotnet test CustomKnife.Core.Tests/CustomKnife.Core.Tests.csproj -c Release
```

Игровая проверка: два игрока, 1/7/8+ ножей, четыре языка и длинные описания;
предпросмотр и подтверждение мышью; масштаб; отзыв прав и reload каталога;
выбор живым/мёртвым зомби → переход в человека без spawn и с respawn;
повторное заражение до отложенной выдачи; отключение и загрузка предпочтения;
закрытие меню при смене роли и освобождение курсора при выгрузке.

Для проверки вёрстки сравните разные ножи с ростом, снижением и равенством
параметров на масштабах 75–125% и экранах 16:9/4:3. Правый край описания должен
совпадать с правым краем превью; в каждой строке видны оба значения, стрелка
и разница с цветом. На крупном масштабе проверьте прокрутку характеристик
до последней строки, а также независимую прокрутку длинного описания.

Таймер работает только при открытых окнах. Нет SQL в обработке клика или
периодической отрисовке. Сетевые строки/классы обновляются только при изменении.
Смена страницы/каталога заменяет HUD-сущность для отклонения старых кликов.

# Интеграция Flute CMS

Начиная с CustomKnife.Core 0.7.0 и ElysiumEquipments 1.19.0, каталог Flute
сохраняет `hud_icon_path` (VSVG списка) и `hud_preview_path` (PNG карточки)
в `custom_knife.knives`. Поле `image_url` остаётся изображением каталога сайта.
Миграцию `20260920120000_AddKnifeHudAssets` выполняет серверный плагин при запуске.
Сначала обновите сервер; CMS покажет понятную ошибку, если новых полей ещё нет.

Название и описание выбираются через ключи ElysiumLocalization. Скорость,
гравитация, урон, отбрасывание, доступность, разрешение, порядок и модель
редактируются в существующей форме «Ножи» Flute. Каталог обновляется в фоне
каждые 5 секунд (`KnifeHud.CatalogRefreshSeconds`, 0 отключает опрос, диапазон
1–300). Открытое меню получает новый снимок на следующем обновлении HUD;
неизменившиеся данные сохраняют сущность и захват мыши. Ошибки БД сохраняют
последний успешный каталог. Ручная команда `custom_knife_reload` также работает.

Обновите Localization.Core до 1.9.0: переводы подхватываются по
`localization.settings.refresh_interval_seconds` (обычно 30 секунд).
Ошибки фонового опроса не заменяют рабочие переводы конфигурационным fallback.
Значения движения обновляются у людей с активным ножом. Модель меняется при
следующей выдаче ножа; обновление каталога не переключает оружие игрока.
Выбор за зомби остаётся сохранённым и применяется при переходе за людей.

Для новых изображений в форме загрузите SVG/VSVG/VSVG_C и PNG, сохраните нож,
затем скачайте «Ресурсы меню ножей» для нужного сервера. Распакуйте архив:

```powershell
./scripts/compile-knife-hud.ps1 -Cs2Path 'C:\CS2' -Addon elysiumhud -CmsExportPath 'C:\knife-hud-export'
```

Скрипт переносит и компилирует исходники, затем XML и три CSS v4. Включите
`elysium_knife_cms_v4.vcss_c`, остальные ресурсы Knife HUD, SVG и PNG в VPK
сервера и клиентов. Без `-CmsExportPath` скрипт сохраняет ранее импортированный
CMS CSS. Для сброса всех картинок импортируйте пустой экспорт CMS.

Экспорт содержит только картинки и отдельный `elysium_knife_cms_v4.css`;
он не заменяет `elysium_equipment_icons_v4.css` магазина и встроенный
`elysium_knife_images_v4.css`. Классы CMS используют SHA-256 пути (первые 32 hex),
поэтому новые имена файлов не требуют пересборки DLL. Базовые классы изображений
остаются на панелях как fallback, если в VPK ещё нет соответствующего класса.
HTTP URL из CMS нельзя использовать как ресурс Panorama: SVG/PNG требуют
компиляции Workshop Tools и обновления VPK; тексты и числа этого не требуют.
