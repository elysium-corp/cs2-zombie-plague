# Ротация карт Elysium

`MapRotation.Core` управляет временем карты, provisional nextmap, номинациями, RTV, голосованием и сменой карты. Все интерактивные экраны используют `CustomHud.Api.ICustomHudMenuApi`. Flute CMS и ограничения карт по количеству игроков в эту версию не входят.

## Установка

1. Выполнить `pwsh ./scripts/build-package.ps1 -Configuration Release`. Установить собранные папки плагинов из `dist/Release/plugins`. Обновляются также `CustomHud.Core`, `CustomKnife.Core`, `Shop.Core` и `Localization.Core`; они согласуют захват ввода через общий API.
2. Создать подключение SwiftlyS2 с именем `map_rotation`, драйвером `postgresql` и отдельной игровой БД этого сервера. Формат подключения такой же, как у `custom_knife` и `shop`. Секреты в репозитории не хранятся. Плагин сам применяет EF-миграцию схемы `map_rotation`.
3. Заполнить `map_rotation.maps` только установленными картами. По умолчанию каталог пуст: ротация отключена, матч работает по серверному конфигу. Плагин не меняет игровые правила, лимиты и гибернацию. Плагин не добавляет неизвестные Zombie-серверу карты. Пример SQL ниже следует адаптировать под свой каталог.
4. Добавить **содержимое** `CustomHud.Core/resources/hud/menus/content/` в существующий addon HUD. Скомпилировать XML/CSS Workshop Tools и добавить полученные ресурсы в общий VPK. Отдельный VPK MapRotation не требуется. У сервера и клиентов должен быть одинаковый обновлённый VPK.
5. Установить обновлённый `Localization.Core`: это обязательная зависимость `MapRotation.Core`. Его миграции добавляют ключи `MapRotation.*`; те же ключи находятся в общем fallback-шаблоне Localization. Выдать администраторам `maprotation.admin`.

## Локализация

Все сообщения HUD, RTV, номинаций, чата и ответы администраторских команд получают текст через `Localization.Api.ILocalizationApi`. Язык игрока, серверный резервный язык и префикс `Elysium` определяет `Localization.Core`. Серверная консоль использует `ServerFallbackLanguage`; `maprotation_status` сохраняет машинный формат JSON.

Переводы редактируются в общем каталоге Localization. Отдельного `MapRotation.Core/resources/translations` и встроенного словаря строк нет. Если ключ отсутствует, выводится полный ключ `MapRotation.*`, а диагностику отсутствующего перевода ведёт Localization. Общий HUD получает уже локализованные строки от вызывающего модуля.

При обновлении существующего сервера применяются новые миграции Localization без перезаписи пользовательских переводов. Для работы без БД обновите проверенный `configs/plugins/Localization.Core/localization.json` экспортом из ElysiumLocalization во Flute CMS; см. [инструкцию Localization.Core](../Localization.Core/README.md). На следующих изменениях обязательно соблюдать раздел «Обязательная локализация» в корневом `AGENTS.md`.

```sql
INSERT INTO map_rotation.maps
    (key, display_name, map_name, workshop_id, sort_order)
VALUES
    ('gorodok', 'Gorodok', 'zm_gorodok_cs2_v1', 3100743780, 10);
-- Добавьте остальные установленные карты. При allow_same_map=false одна текущая карта
-- не образует ротацию; в каталоге нужна ещё одна допустимая карта.
UPDATE map_rotation.settings
SET configuration_version = configuration_version + 1 WHERE id = 1;
```

Настройки по умолчанию соответствуют ТЗ: 45 минут на карту, голосование за 5 минут до конца на 20 секунд, 6 кандидатов, 3 слота номинаций, RTV 60% с минимумом 3 голоса и 4 игрока, задержка RTV 5 минут. Настройки и каталог перечитываются фоново раз в `refresh_interval_seconds` (15 секунд).

## Команды

| Команда | Поведение |
|---|---|
| `!timeleft` | Карточка MM:SS; после deadline — последний раунд |
| `!nextmap` | Карточка следующей карты |
| `!rtv` | Один запрос на SteamID; при активном vote повторно открывает HUD |
| `!nominate` | HUD номинаций с пагинацией |
| `!nominate <key или map_name>` | Добавить или заменить свою номинацию |
| `maprotation_status` | JSON ротации, снимок движка `Engine` и сводка каталога `Catalog` |
| `maprotation_maps` | Сводка БД и отдельная JSON-строка для каждой карты с причинами исключения |
| `maprotation_reload` | Запросить фоновое обновление настроек и каталога |
| `maprotation_vote` | Начать общее голосование, если следующая карта ещё не зафиксирована |
| `maprotation_setnext <key или map_name>` | Зафиксировать карту администратором и отменить текущий vote |
| `maprotation_change <key или map_name>` | Проверить и сменить карту через Engine API |

Команды `maprotation_*` требуют `maprotation.admin` для игрока; серверная консоль разрешена. Параметры команд никогда не конкатенируются в команду движка: сначала находится запись каталога и проверяется `Engine.IsMapValid`.

При пустом доступном пуле игровые команды и команды запуска голосования/смены карты отвечают через Localization, что ротация отключена; HUD не открывается. Диагностика `maprotation_status`, команда `maprotation_reload` и фоновое чтение каталога продолжают работать. После добавления разрешённых установленных карт ротация включается автоматически при следующем обновлении каталога, без перезапуска плагина.

## Правила работы

- Состояния: Loading → Playing → Voting → NextMapSelected → FinalRound → ChangingMap. На deadline существующий vote может завершиться в FinalRound; `round_end` завершает его перед сменой карты. Warmup и GameCommencing не завершают последний раунд.
- Время считается через `TimeProvider`. На пустом сервере часы карты, задержка RTV, голосование и timeout последнего раунда приостанавливаются; боты не возобновляют часы. При появлении человека сохраняется неиспользованный остаток времени, а не выдаётся новый полный интервал. Настройки допуска наблюдателей к голосованию не влияют на учёт присутствующих людей.
- Пустой доступный пул полностью отключает ротацию: голосования и смена карты не запускаются, HUD закрывается. Нативный матч, его лимиты и гибернация работают как без MapRotation; плагин продолжает только чтение каталога, учёт своего состояния и диагностику. Удаление или отключение последней доступной карты отменяет активное голосование и отложенную смену, очищает RTV и номинации. Отключённые, неустановленные карты и текущая карта при `allow_same_map=false` не считаются доступным пулом. При заполнении пула часы продолжают отсчёт с сохранённого остатка; до первого запуска он равен полной длительности карты.
- Если следующая карта отсутствует и нет кандидатов голосования, ротация ждёт заполнения каталога. Карты только для голосования остаются доступны через RTV или команду администратора даже при отключённом плановом голосовании. В `FinalRound` без цели или активного голосования ротация не переходит. Старый сохранённый `FinalRound` без карты и голосования восстанавливается в `Playing` с новым интервалом; уже сыгранная история сохраняется.
- Горячая перезагрузка на той же фактической карте восстанавливает кандидатов, голоса, nextmap и остаток времени, включая сохранённую паузу. Настройка длительности применяется со следующей карты. Дополнительные поля checkpoint сохраняются в существующем JSON, отдельная миграция БД не нужна.
- Успешный RTV с `end_of_round` делает текущий раунд последним. `immediate` поддерживается явно; `rtv_change_delay_seconds` применяется после соответствующего события. Timeout последнего раунда вызывает принудительную смену с предупреждением.
- Смена отправляется на следующем world update, после завершения обработчиков game-event. Перед отправкой повторно проверяется карта. Отсутствие map-load в течение 30 секунд считается неудачей; выбирается другая допустимая карта с ограничением частоты повторов.
- Номинации группируются по числу игроков. Из лидеров берутся `nomination_slots`, оставшиеся кандидаты выбираются по весам без повторов. Равенство голосов/номинаций решает внедряемый RNG. Кандидаты активного vote не меняются при reload, но отключённая или удалённая карта не может победить.
- Cooldown проверяется по истории завершённых карт. При нехватке кандидатов ослабляется сначала индивидуальный, затем общий cooldown. Если auto-пул пуст, явно заданный `fallback_map_id` может использоваться даже вне auto-пула; disabled, current при запрете повторов и неустановленные карты запрещены всегда. Fallback не попадает в номинации или vote в обход их флагов.
- Один SteamID имеет одну номинацию, один RTV и один действующий бюллетень. Повторный выбор заменяет бюллетень. Disconnect/потеря права участия удаляет участие; подключение и изменение количества игроков пересчитывает порог. При `exclude_bots=false` боты учитываются в численности, но не создают голоса.
- С `1.1.0` при активном пуле MapRotation читает `mp_timelimit`, `mp_maxrounds`, `mp_winlimit` и `mp_match_can_clinch`, не переписывая их. Время CS2 считается от `GameStartTime`; для прогноза конца матча используются сыгранные раунды и счёт команд. Голосование запускается заранее по нативному времени или при двух оставшихся раундах/победах. При выключенном `scheduled_vote_enabled` эти наблюдения не запускают голосование.
- Собственный `map_duration_seconds` сохраняется вместе с паузой без людей. Серверный лимит может завершить матч раньше: `timeleft` и `TimeLeftSeconds` показывают меньший из действующих временных лимитов. Исходный deadline ротации хранится отдельно в checkpoint; его не заменяют снимком времени CS2.
- С `1.1.1` MapRotation вообще не записывает ConVar, включая `mp_timelimit`, `mp_maxrounds`, `mp_winlimit` и `sv_hibernate_when_empty`. При `NoMaps` обработчики раундов и завершения матча пропускают игровую логику ротации. Появление доступных карт автоматически активирует ротацию после обновления каталога.
- `mp_match_end_changelevel`, `mp_match_end_restart` и `sv_hibernate_when_empty` остаются под управлением серверного конфига. Плагин не выполняет `mp_restartgame`, не переписывает `FreezePeriod`/`GamePhase` и не перезагружает текущую карту по watchdog.
- Событие `cs_win_panel_match` запоминает штатное завершение матча. Начатое голосование сохраняет полный срок; после выбора карты переход отправляется через 3 секунды, с учётом большей задержки RTV. Если плановое голосование разрешено, неожиданное завершение также может запустить его. Повторное событие не дублирует переход. Без людей переход ждёт возвращения игрока, при `NoMaps` не выполняется. Новая сессия карты сбрасывает признак завершения; горячая перезагрузка плагина на прежней сессии сохраняет его в checkpoint.
- Единственные команды движку — `changelevel`/`host_workshop_map` для разрешённой карты при действующей ротации. Плагин не устанавливает нулевые лимиты даже временно при загрузке или отсутствии БД.
- SQL не выполняется из vote/click/render/tick. Фоновый worker сохраняет immutable-снимки не чаще `refresh_interval_seconds`; выгрузка делает финальное сохранение. `rotation-state.json` записывается атомарно и содержит незаписанную историю/результаты для повтора после отказа БД. Повтор записи истории идемпотентен.
- Каталог и settings читаются одной транзакцией RepeatableRead. Ошибка БД или невалидная конфигурация сохраняет последний корректный снимок. Каждый успешный refresh, включая `maprotation_reload`, повторяет проверку установленности карт на игровом потоке даже при неизменившихся строках БД.

## HUD

Ресурсы называются `elysium_menu_v4.xml/css`; отдельная тема MapRotation — `elysium_map_rotation_v4.css`. Суффикс — версия общего шаблона, не версия компилятора Valve. Корневая панель без id; JS и обработчики `onactivate` отсутствуют.

Один fullscreen menu на игрока. Vote имеет Critical priority, номинации — Normal. Открытие общего меню закрывает HUD магазина и ножей. ESC закрывает интерфейс, но не удаляет уже поданный голос; `!rtv` открывает активное голосование снова. Новая страница получает новую entity, поэтому отложенный клик старой страницы не выбирает другой пункт.

Дизайн работает без обязательных изображений карт: используется нейтральная пиктограмма. Карточки `!timeleft`/`!nextmap`/`!rtv` отправляются через существующий API баннеров. Отсутствие ресурсов меню не отключает сообщения/баннеры; пользователю приходит локализованное уведомление в чат. Текстовые команды не заменяются стандартным Swiftly Menu API.

Макеты: [общий вид](../docs/map-rotation/previews/overview.png), [номинации](../docs/map-rotation/previews/nomination.png), [голосование](../docs/map-rotation/previews/vote.png), [результат](../docs/map-rotation/previews/result.png), [компактные карточки](../docs/map-rotation/previews/cards.png). Это браузерная адаптация фактических XML/CSS с данными примера, не игровые скриншоты. Генератор: `python scripts/hud-preview/render-menu.py`, затем `node scripts/hud-preview/capture.mjs` с установленным Playwright. `HUD_PREVIEW_CHROMIUM` позволяет указать локальный Chromium.

## Подключение после простоя

`State: 4` в `maprotation_status` означает `FinalRound` ротации, а не состояние игрового раунда Zombie Plague. Статус дополнительно выводит `RotationEnabled`, `PauseReason`: `None`, `EmptyServer` или `NoMaps`, и `TimeLeftSeconds`. При пустом доступном пуле: `RotationEnabled: false`, `PauseReason: "NoMaps"`, `TimeLeftSeconds: null` — таймер MapRotation отключён; продолжительность матча задаёт серверный конфиг. `NoMaps` имеет приоритет над отсутствием игроков. При `EmptyServer` остаток секунд фиксирован; `Deadline` показывает срок при немедленном возобновлении часов. При `NoMaps` значение `Deadline` не является действующим ограничением.

`NextMap: null` требует проверить каталог и установленность карт; если все кандидаты исключены, выводится `PauseReason: "NoMaps"`. Это не должно мешать игре на текущей карте. При стандартном `allow_same_map=false` одной текущей карты в каталоге недостаточно.

### Карты из БД не видны

После `maprotation_reload` дождаться фонового обновления и выполнить `maprotation_maps`. Первая строка содержит `Catalog`: имя подключения (`map_rotation`), фактическое имя БД, источник действующего снимка, время последнего успешного чтения и тип последней ошибки. Пароли, адрес подключения и текст исключений не выводятся. `Source=LocalSnapshot` означает, что загружен локальный снимок; `Source=Empty` — что снимка нет и БД ещё не прочитана успешно. При ошибке обновления последний корректный каталог сохраняется, а подробности ошибки остаются в серверном логе.

Далее каждая карта выводится отдельной JSON-строкой. `PoolExclusion` объясняет базовое исключение из ротации, `NominationExclusion` — отсутствие в списке номинаций; `null` означает отсутствие соответствующего запрета. Флаги строки БД показаны отдельно.

| Код | Причина |
|---|---|
| `Disabled` | `enabled=false` |
| `EngineRejected` | Карта не принята проверкой движка или последняя смена на неё не удалась |
| `CurrentMap` | Это текущая карта, а `allow_same_map=false` |
| `NoVotingOrRotation` | Выключены голосование и автоматическая ротация, карта не назначена fallback |
| `NominationsDisabled` | Номинации выключены в settings |
| `NominationDisabled` | `allow_nomination=false` у карты |
| `VotingDisabled` | `allow_vote=false` у карты |
| `RecentMap` | Карта исключена из текущих кандидатов по истории/cooldown |

Добавление в БД не скачивает карту на сервер. При `EngineRejected` проверить Workshop ID, имя карты и её файлы. После установки достаточно `maprotation_reload`; менять версию настроек ради повторной проверки файлов больше не требуется. Если загружено ноль карт, сопоставить имя БД в диагностике с БД, в которой выполнялся INSERT.

### Диагностика таймера 0:00 и блокировки движения

Начиная с `MapRotation.Core 1.0.1`, `maprotation_status` дополнительно возвращает `Engine`. Снимок собирается только при выполнении команды, на игровом потоке, без изменения игровых правил. Старые поля статуса сохранены; `State: 1` означает `Playing` ротации и не доказывает, что игровой матч запущен.

- `Engine.Globals`: `FrameCount`, `TickCount`, `CurrentTime`, `FrameTime`, `RealTime`. Сравнить два вывода с интервалом 5–10 секунд, чтобы увидеть, продвигается ли симуляция.
- `Engine.Rules`: фаза матча, `GamePaused`, `MatchWaitingForResume`, `FreezePeriod`, `WarmupPeriod`, тайм-ауты, время перезапуска/интермиссии и количество участников команд. Это данные игровых правил CS2, независимые от состояния ротации.
- `Engine.Players`: команда, жизнь, здоровье, флаги, тип движения и `VelocityModifier` подключённых людей. SteamID, IP и имена в снимок не включаются.
- `Engine.ConVars`: параметры матча и настройки гибернации. `sv_hibernate_when_empty` — разрешение гибернации, а не её фактическое состояние. `Engine.Overrides` сохранён для совместимости и с `1.1.1` всегда пуст: плагин не изменяет ConVar.
- `Engine.PendingConVars` сохранён для совместимости и с `1.1.1` всегда пуст. Снимок статуса не исполняет команды и не изменяет игровые правила.
- Ошибка чтения отдельного раздела возвращается в его `Error`; остальные разделы и исходный статус ротации остаются доступны. Результат отражает момент выполнения команды и не является автоматическим диагнозом.

В `1.0.2` добавлены `LastThinkTime`, `TmNextPeriodicThink`, счётчики раундов,
`TimeUntilNextPhaseStarts`, `mp_halftime_pausetimer` и `mp_team_intro_time`.
Если `CurrentTime` растёт, а `LastThinkTime` не меняется, следует проверять
выполнение игровых правил. `FreezePeriod=true` при истёкшем времени заморозки
и выключенных паузах подтверждает зависшую фазу, но не указывает её причину.
Плагин не сбрасывает `FreezePeriod` вручную и не имитирует события раунда.

В `1.1.0` добавлены `GameStartTime`, `mp_match_can_clinch`, `sv_hibernate_when_empty` и `sv_hibernate_postgame_delay` в диагностику. Изменение checkpoint обратно совместимо и не требует миграции БД.

При переработке использован подход [TimeLimitManager](https://github.com/abnerfs/cs2-rockthevote/blob/0bc827ad395db8fd9fc10402b3aef824f2bb886a/Core/TimeLimitManager.cs), [MaxRoundsManager](https://github.com/abnerfs/cs2-rockthevote/blob/0bc827ad395db8fd9fc10402b3aef824f2bb886a/Core/MaxRoundsManager.cs) и [ChangeMapManager](https://github.com/abnerfs/cs2-rockthevote/blob/0bc827ad395db8fd9fc10402b3aef824f2bb886a/Core/ChangeMapManager.cs) из `abnerfs/cs2-rockthevote`: чтение нативных ограничений и реакция на завершение матча. Наш код сохраняет SwiftlyS2, собственное расписание с паузой без игроков, Localization и HUD. Упомянутый в [открытом PR #92](https://github.com/abnerfs/cs2-rockthevote/pull/92) случай завершения голосования после конца матча обработан отдельно; периодическая перезагрузка старой карты не переносилась.

Наблюдения 24.09.2026 не доказывают причину зависания: `LastThinkTime` останавливался при растущем `CurrentTime`, позднее сервер оставался в `GAMEPHASE_MATCH_ENDED`. Замена способа записи ConVar и ручной `mp_match_end_restart 1` не восстановили матч. После `sv_hibernate_when_empty 0` вместе с `changelevel` пользователь подтвердил восстановление игры; эффект изменения настройки отдельно от перезагрузки карты не установлен. В `1.1.1` отключение гибернации не применяется: по требованию владельца сервера полностью удалено вмешательство MapRotation в настройки матча. Проверки .NET подтверждают логику плагина, но не заменяют проверку переподключения на CS2.

Проверка новой сборки в CS2:

1. Перезапустить сервер после замены старой сборки, чтобы заново применить серверные конфиги: новый экземпляр не может восстановить утраченные исходные значения прежнего.
2. При пустом пуле проверить нулевые лимиты, `NoMaps`, обычный старт раунда, затем выход всех людей и повторный вход. Записать фактическое значение `sv_hibernate_when_empty`; отдельно проверить исходный сценарий с разрешённой гибернацией.
3. При заполненном пуле проверить сохранение серверных лимитов и `mp_match_end_*`. При коротком `mp_timelimit` либо близком лимите раундов дождаться голосования и завершения матча. Проверить, что победившая карта загружается один раз, в том числе когда голосование заканчивается после `cs_win_panel_match`.
4. Проверить возврат лимитов после заполнения пула, очистку пула во время голосования, горячую перезагрузку и смену карты. Без пула плагин не вызывает `changelevel`, даже если движок уже завершил матч.

Если игра уже зависла, сначала сохранить два `maprotation_status` с интервалом 5–10 секунд и лог вокруг disconnect/connect. Для восстановления известен перезапуск карты/сервера; новая версия не пытается чинить остановившиеся игровые правила прямой записью флагов.

Подготовка Zombie Plague не расходует отсчёт без живых участников и сохраняет возможность возродить подключившегося игрока человеком. Когда участник готов, начинается полный `PreStartDelay`; завершённый или отменённый раунд автоматически не перезапускается.

Исправление простоя требует обновить `MapRotation.Api`, `MapRotation.Core`, `ZombiePlague.Core` и `Localization.Core` из одной сборки. Новые тексты отсутствия пула добавлены отдельной миграцией Localization и в общий fallback-шаблон без перезаписи пользовательских переводов. После установки на уже зависший сервер перезапустить сервер или перезагрузить карту, чтобы заново запустить игровой lifecycle. Проверить: пустая карта дольше 45 минут → подключение человека → появление отсчёта заражения; затем выход всех игроков и повторное подключение. При заполненном пуле время ротации не расходуется без людей; при пустом пуле плагин не вмешивается в нативный матч. Дополнительно проверить заполнение и очистку пула без перезапуска, включая очистку во время голосования.

## Проверка в CS2 перед включением

.NET-сборка и тесты не заменяют компиляцию Panorama. Нужно скомпилировать ресурсы актуальными Workshop Tools, смонтировать общий VPK и проверить клики, ESC, страницы, RTV при открытом магазине/ножах, hot reload активного vote, stock и установленную Workshop-карту. Также проверить подключение PostgreSQL, заполнение каталога и права `maprotation.admin`. На рабочий сервер изменения автоматически не устанавливаются.


## Flute CMS и изображения (1.2.0)

Интеграция с `[Elysium] Map Rotation` на сайте требует CustomHud.Core **1.6.0** и ElysiumPlatform **1.11.0**. Миграция `20260924150000_AddMapRotationCmsPresentation` добавляет `maps.hud_image_path`, `settings.hud_settings` и `settings.menu_items_per_page` (1–6, по умолчанию 5), сохраняя существующие карты и настройки.

В Flute привязать мод `elysium_map_rotation` к БД конкретного игрового сервера. Страница `/admin/elysium/map-rotation` редактирует только настройки и карты. Каталог разных серверов изолируется отдельными БД. `hud_settings` хранит настройки редактора; плагин получает изображения и число строк, а оформление загружается из скомпилированной темы в общем HUD-пакете.

Изображения разрешены только из `panorama/images/custom_game/elysium/assets/<sha256>_png.vtex`. CustomHud сбрасывает классы старой миниатюры при обновлении пункта, поэтому новая карта не сохраняет чужую картинку. XML/CSS v4, тема и используемые VTEX должны быть скомпилированы актуальными CS2 Workshop Tools и находиться в одном общем `elysiumhud` VPK на сервере и клиентах. Экспорт сайта содержит исходники и `compile.ps1` для импорта в существующий addon; отдельный MapRotation VPK не нужен. Браузерное превью не заменяет проверку в движке.

После обновления плагинов и ресурсов выполнить `changelevel` для выхода из уже зависшего матча. Гибернацию менять не требуется. Наличие записей и причины исключения проверяются через `maprotation_maps`; для единственной текущей карты нужно разрешить `allow_same_map`, чтобы она была доступна для ротации.
