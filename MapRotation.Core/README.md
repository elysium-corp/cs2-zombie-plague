# Ротация карт Elysium

`MapRotation.Core` управляет временем карты, provisional nextmap, номинациями, RTV, голосованием и сменой карты. Все интерактивные экраны используют `CustomHud.Api.ICustomHudMenuApi`. Flute CMS и ограничения карт по количеству игроков в эту версию не входят.

## Установка

1. Выполнить `pwsh ./scripts/build-package.ps1 -Configuration Release`. Установить собранные папки плагинов из `dist/Release/plugins`. Обновляются также `CustomHud.Core`, `CustomKnife.Core`, `Shop.Core` и `Localization.Core`; они согласуют захват ввода через общий API.
2. Создать подключение SwiftlyS2 с именем `map_rotation`, драйвером `postgresql` и отдельной игровой БД этого сервера. Формат подключения такой же, как у `custom_knife` и `shop`. Секреты в репозитории не хранятся. Плагин сам применяет EF-миграцию схемы `map_rotation`.
3. Заполнить `map_rotation.maps` только установленными картами. По умолчанию каталог пуст: ротация отключена, текущая карта работает без ограничения времени, игровые раунды продолжаются. Плагин не добавляет неизвестные Zombie-серверу карты. Пример SQL ниже следует адаптировать под свой каталог.
4. Добавить **содержимое** `CustomHud.Core/resources/hud/menus/content/` в существующий addon HUD. Скомпилировать XML/CSS Workshop Tools и добавить полученные ресурсы в общий VPK. Отдельный VPK MapRotation не требуется. У сервера и клиентов должен быть одинаковый обновлённый VPK.
5. Установить обновлённый `Localization.Core`: это обязательная зависимость `MapRotation.Core`. Его миграции добавляют ключи `MapRotation.*`; те же ключи находятся в общем fallback-шаблоне Localization. Выдать администраторам `maprotation.admin`.

## Локализация

Все сообщения HUD, RTV, номинаций, чата и ответы администраторских команд получают текст через `Localization.Api.ILocalizationApi`. Язык игрока, серверный резервный язык и префикс `Elysium` определяет `Localization.Core`. Серверная консоль использует `ServerFallbackLanguage`; `maprotation_status` сохраняет машинный формат JSON.

Переводы редактируются в общем каталоге Localization. Отдельного `MapRotation.Core/resources/translations` и встроенного словаря строк нет. Если ключ отсутствует, выводится полный ключ `MapRotation.*`, а диагностику отсутствующего перевода ведёт Localization. Общий HUD получает уже локализованные строки от вызывающего модуля.

При обновлении существующего сервера применяются новые миграции Localization без перезаписи пользовательских переводов. Для работы без БД обновите проверенный `configs/plugins/Localization.Core/localization.json` экспортом из ElysiumLocalization во Flute CMS; см. [инструкцию Localization.Core](../Localization.Core/README.md). На следующих изменениях обязательно соблюдать раздел «Обязательная локализация» в корневом `AGENTS.md`.

```sql
INSERT INTO map_rotation.maps
    (key, display_name, map_name, workshop_id, sort_order)
VALUES
    ('gorodok', 'Gorodok', 'zm_gorodok_cs2_v1', 3100743780, 10);
-- Добавьте остальные установленные карты. При allow_same_map=false одна текущая карта
-- не образует ротацию; в каталоге нужна ещё одна допустимая карта.
UPDATE map_rotation.settings
SET configuration_version = configuration_version + 1 WHERE id = 1;
```

Настройки по умолчанию соответствуют ТЗ: 45 минут на карту, голосование за 5 минут до конца на 20 секунд, 6 кандидатов, 3 слота номинаций, RTV 60% с минимумом 3 голоса и 4 игрока, задержка RTV 5 минут. Настройки и каталог перечитываются фоново раз в `refresh_interval_seconds` (15 секунд).

## Команды

| Команда | Поведение |
|---|---|
| `!timeleft` | Карточка MM:SS; после deadline — последний раунд |
| `!nextmap` | Карточка следующей карты |
| `!rtv` | Один запрос на SteamID; при активном vote повторно открывает HUD |
| `!nominate` | HUD номинаций с пагинацией |
| `!nominate <key или map_name>` | Добавить или заменить свою номинацию |
| `maprotation_status` | JSON ротации и снимок движка в поле `Engine` |
| `maprotation_reload` | Запросить фоновое обновление настроек и каталога |
| `maprotation_vote` | Начать общее голосование, если следующая карта ещё не зафиксирована |
| `maprotation_setnext <key или map_name>` | Зафиксировать карту администратором и отменить текущий vote |
| `maprotation_change <key или map_name>` | Проверить и сменить карту через Engine API |

Последние пять команд требуют `maprotation.admin` для игрока; серверная консоль разрешена. Параметры команд никогда не конкатенируются в команду движка: сначала находится запись каталога и проверяется `Engine.IsMapValid`.

При пустом доступном пуле игровые команды и команды запуска голосования/смены карты отвечают через Localization, что ротация отключена и карта не ограничена по времени; HUD не открывается. Диагностика `maprotation_status`, команда `maprotation_reload` и фоновое чтение каталога продолжают работать. После добавления разрешённых установленных карт ротация включается автоматически при следующем обновлении каталога, без перезапуска плагина.

## Правила работы

- Состояния: Loading → Playing → Voting → NextMapSelected → FinalRound → ChangingMap. На deadline существующий vote может завершиться в FinalRound; `round_end` завершает его перед сменой карты. Warmup и GameCommencing не завершают последний раунд.
- Время считается через `TimeProvider`. На пустом сервере часы карты, задержка RTV, голосование и timeout последнего раунда приостанавливаются; боты не возобновляют часы. При появлении человека сохраняется неиспользованный остаток времени, а не выдаётся новый полный интервал. Настройки допуска наблюдателей к голосованию не влияют на учёт присутствующих людей.
- Пустой доступный пул полностью отключает ротацию: карта бессрочна, голосования и смена карты не запускаются, HUD закрывается. Удаление или отключение последней доступной карты отменяет активное голосование и отложенную смену, очищает RTV и номинации. Отключённые, неустановленные карты и текущая карта при `allow_same_map=false` не считаются доступным пулом. При заполнении пула часы продолжают отсчёт с сохранённого остатка; до первого запуска он равен полной длительности карты.
- Если следующая карта отсутствует и нет кандидатов голосования, ротация ждёт заполнения каталога. Карты только для голосования остаются доступны через RTV или команду администратора даже при отключённом плановом голосовании. В `FinalRound` без цели или активного голосования ротация не переходит. Старый сохранённый `FinalRound` без карты и голосования восстанавливается в `Playing` с новым интервалом; уже сыгранная история сохраняется.
- Горячая перезагрузка на той же фактической карте восстанавливает кандидатов, голоса, nextmap и остаток времени, включая сохранённую паузу. Настройка длительности применяется со следующей карты. Дополнительные поля checkpoint сохраняются в существующем JSON, отдельная миграция БД не нужна.
- Успешный RTV с `end_of_round` делает текущий раунд последним. `immediate` поддерживается явно; `rtv_change_delay_seconds` применяется после соответствующего события. Timeout последнего раунда вызывает принудительную смену с предупреждением.
- Смена отправляется на следующем world update, после завершения обработчиков game-event. Перед отправкой повторно проверяется карта. Отсутствие map-load в течение 30 секунд считается неудачей; выбирается другая допустимая карта с ограничением частоты повторов.
- Номинации группируются по числу игроков. Из лидеров берутся `nomination_slots`, оставшиеся кандидаты выбираются по весам без повторов. Равенство голосов/номинаций решает внедряемый RNG. Кандидаты активного vote не меняются при reload, но отключённая или удалённая карта не может победить.
- Cooldown проверяется по истории завершённых карт. При нехватке кандидатов ослабляется сначала индивидуальный, затем общий cooldown. Если auto-пул пуст, явно заданный `fallback_map_id` может использоваться даже вне auto-пула; disabled, current при запрете повторов и неустановленные карты запрещены всегда. Fallback не попадает в номинации или vote в обход их флагов.
- Один SteamID имеет одну номинацию, один RTV и один действующий бюллетень. Повторный выбор заменяет бюллетень. Disconnect/потеря права участия удаляет участие; подключение и изменение количества игроков пересчитывает порог. При `exclude_bots=false` боты учитываются в численности, но не создают голоса.
- `mp_timelimit`, `mp_maxrounds` и `mp_winlimit` удерживаются в 0, в том числе при пустом пуле, чтобы текущая карта оставалась бессрочной. `mp_match_end_changelevel` и `mp_match_end_restart` обнуляются только при активной ротации; при переходе в `NoMaps` плагин восстанавливает свои изменения этих двух настроек. При старте с пустым пулом их серверные значения сохраняются. Это не включает автоматический рестарт, если он уже отключён серверным конфигом.
- С `1.0.3` настройки записываются и восстанавливаются серверными командами через `Engine.ExecuteCommand`. Плагин не вызывает setters `Value`/`ValueAsString`. В команду допускаются только пять перечисленных параметров и числовые аргументы, отформатированные с `InvariantCulture`.
- Отправленная команда учитывается отдельно от подтверждённого изменения. Таймер только читает ожидающие значения; после подтверждения запоминается нормализованная движком строка (`false`, `0.000000`). Если значение не подтверждено за 5 секунд, запись снимается с учёта с предупреждением в техническом логе. Автоматического повторения команды из таймера нет.
- При выгрузке подтверждённые значения восстанавливаются, если остались под управлением плагина. Для ещё ожидающей команды восстановление ставится вслед за ней в очередь движка. Внешнее изменение, обнаруженное до отправки восстановления, сохраняется. Повторная загрузка карты учитывает новый конфиг и заново запрашивает неподтверждённые ограничения. Политика проверяется при смене доступности ротации, загрузке карты и старте раунда.
- SQL не выполняется из vote/click/render/tick. Фоновый worker сохраняет immutable-снимки не чаще `refresh_interval_seconds`; выгрузка делает финальное сохранение. `rotation-state.json` записывается атомарно и содержит незаписанную историю/результаты для повтора после отказа БД. Повтор записи истории идемпотентен.
- Каталог и settings читаются одной транзакцией RepeatableRead. Ошибка БД или невалидная конфигурация сохраняет последний корректный снимок.

## HUD

Ресурсы называются `elysium_menu_v1.xml/css`, как прямо указано в ТЗ. Суффикс — версия общего шаблона, не версия компилятора Valve. Корневая панель без id; JS и обработчики `onactivate` отсутствуют.

Один fullscreen menu на игрока. Vote имеет Critical priority, номинации — Normal. Открытие общего меню закрывает HUD магазина и ножей. ESC закрывает интерфейс, но не удаляет уже поданный голос; `!rtv` открывает активное голосование снова. Новая страница получает новую entity, поэтому отложенный клик старой страницы не выбирает другой пункт.

Дизайн работает без обязательных изображений карт: используется нейтральная пиктограмма. Карточки `!timeleft`/`!nextmap`/`!rtv` отправляются через существующий API баннеров. Отсутствие ресурсов меню не отключает сообщения/баннеры; пользователю приходит локализованное уведомление в чат. Текстовые команды не заменяются стандартным Swiftly Menu API.

Макеты: [общий вид](../docs/map-rotation/previews/overview.png), [номинации](../docs/map-rotation/previews/nomination.png), [голосование](../docs/map-rotation/previews/vote.png), [результат](../docs/map-rotation/previews/result.png), [компактные карточки](../docs/map-rotation/previews/cards.png). Это браузерная адаптация фактических XML/CSS с данными примера, не игровые скриншоты. Генератор: `python scripts/hud-preview/render-menu.py`, затем `node scripts/hud-preview/capture.mjs` с установленным Playwright. `HUD_PREVIEW_CHROMIUM` позволяет указать локальный Chromium.

## Подключение после простоя

`State: 4` в `maprotation_status` означает `FinalRound` ротации, а не состояние игрового раунда Zombie Plague. Статус дополнительно выводит `RotationEnabled`, `PauseReason`: `None`, `EmptyServer` или `NoMaps`, и `TimeLeftSeconds`. При пустом доступном пуле: `RotationEnabled: false`, `PauseReason: "NoMaps"`, `TimeLeftSeconds: null` — карта без ограничения времени. `NoMaps` имеет приоритет над отсутствием игроков. При `EmptyServer` остаток секунд фиксирован; `Deadline` показывает срок при немедленном возобновлении часов. При `NoMaps` значение `Deadline` не является действующим ограничением.

`NextMap: null` требует проверить каталог и установленность карт; если все кандидаты исключены, выводится `PauseReason: "NoMaps"`. Это не должно мешать игре на текущей карте. При стандартном `allow_same_map=false` одной текущей карты в каталоге недостаточно.

### Диагностика таймера 0:00 и блокировки движения

Начиная с `MapRotation.Core 1.0.1`, `maprotation_status` дополнительно возвращает `Engine`. Снимок собирается только при выполнении команды, на игровом потоке, без изменения игровых правил. Старые поля статуса сохранены; `State: 1` означает `Playing` ротации и не доказывает, что игровой матч запущен.

- `Engine.Globals`: `FrameCount`, `TickCount`, `CurrentTime`, `FrameTime`, `RealTime`. Сравнить два вывода с интервалом 5–10 секунд, чтобы увидеть, продвигается ли симуляция.
- `Engine.Rules`: фаза матча, `GamePaused`, `MatchWaitingForResume`, `FreezePeriod`, `WarmupPeriod`, тайм-ауты, время перезапуска/интермиссии и количество участников команд. Это данные игровых правил CS2, независимые от состояния ротации.
- `Engine.Players`: команда, жизнь, здоровье, флаги, тип движения и `VelocityModifier` подключённых людей. SteamID, IP и имена в снимок не включаются.
- `Engine.ConVars`: только перечисленные в диагностике параметры матча; `Engine.Overrides` показывает исходные и фактически записанные этим экземпляром значения. При `NoMaps` среди изменений не должно быть `mp_match_end_restart` и `mp_match_end_changelevel`.
- `Engine.PendingConVars` (с `1.0.3`): отправленные, но ещё не подтверждённые команды. `Requested` — запрошенное значение, `Restoring` — восстановление вместо применения политики. Снимок статуса сам не исполняет команды и не подтверждает их.
- Ошибка чтения отдельного раздела возвращается в его `Error`; остальные разделы и исходный статус ротации остаются доступны. Результат отражает момент выполнения команды и не является автоматическим диагнозом.

В `1.0.2` добавлены `LastThinkTime`, `TmNextPeriodicThink`, счётчики раундов,
`TimeUntilNextPhaseStarts`, `mp_halftime_pausetimer` и `mp_team_intro_time`.
Если `CurrentTime` растёт, а `LastThinkTime` не меняется, следует проверять
выполнение игровых правил. `FreezePeriod=true` при истёкшем времени заморозки
и выключенных паузах подтверждает зависшую фазу, но не указывает её причину.
Плагин не сбрасывает `FreezePeriod` вручную и не имитирует события раунда.

Замена строкового setter на типизированный в `1.0.2` не устранила зависание на
проверяемом сервере. Контрольная проверка 24.09.2026: после выгрузки плагина и
`changelevel` игра восстановилась; консольные `mp_maxrounds 0` и `mp_restartgame 1`
прошли успешно. Загрузка MapRotation с уже нулевыми лимитами дала `Overrides: {}`,
`FreezePeriod: false`, `LastThinkTime == CurrentTime`. Это указывает на применение
настроек или момент применения, но не доказывает конкретный дефект SwiftlyS2/CS2.

В `1.0.3` используется консольный путь, прошедший эту ручную проверку.
[`Engine.ExecuteCommand` SwiftlyS2 1.4.11](https://github.com/swiftly-solution/swiftlys2/blob/v1.4.11/src/scripting/engine/enginehelpers.cpp)
передаёт команду в `ServerCommand`, поэтому выполнение и подтверждение разделены.
Исправление сохраняет бессрочную карту при пустом пуле. Оно не сбрасывает игровые
флаги и не выполняет `mp_restartgame` автоматически.

Проверка новой сборки в CS2: загрузить карту с MapRotation `1.0.3` и исходным
`mp_maxrounds 30`; убедиться, что лимит стал `0`, `PendingConVars` опустел,
движение работает, `LastThinkTime` продвигается, следующий раунд начинается.
Затем проверить `changelevel` с загруженным плагином и подключение после простоя.
Успешная ручная проверка консольной команды не заменяет эту проверку сборки.

После замены старой версии сделать полный перезапуск сервера, чтобы заново исполнить серверные конфиги: новый экземпляр не может восстановить утраченные исходные значения предыдущего экземпляра. Если игра снова остановится, сохранить два вывода `maprotation_status` с интервалом 5–10 секунд и серверный лог от загрузки карты до проблемы. До снятия данных не сбрасывать флаги игровых правил вручную.

Для сравнения использованы [TimeLimitManager](https://github.com/abnerfs/cs2-rockthevote/blob/0bc827ad395db8fd9fc10402b3aef824f2bb886a/Core/TimeLimitManager.cs), [MaxRoundsManager](https://github.com/abnerfs/cs2-rockthevote/blob/0bc827ad395db8fd9fc10402b3aef824f2bb886a/Core/MaxRoundsManager.cs) и [ChangeMapManager](https://github.com/abnerfs/cs2-rockthevote/blob/0bc827ad395db8fd9fc10402b3aef824f2bb886a/Core/ChangeMapManager.cs) из `abnerfs/cs2-rockthevote`: чтение нативных лимитов и переход после событий раунда/матча. Его реализация использует CounterStrikeSharp; наш модуль сохраняет SwiftlyS2, общую Localization и HUD. Это сравнение архитектуры, а не подтверждение причины остановки конкретного сервера.

Подготовка Zombie Plague не расходует отсчёт без живых участников и сохраняет возможность возродить подключившегося игрока человеком. Когда участник готов, начинается полный `PreStartDelay`; завершённый или отменённый раунд автоматически не перезапускается.

Исправление простоя требует обновить `MapRotation.Api`, `MapRotation.Core`, `ZombiePlague.Core` и `Localization.Core` из одной сборки. Новые тексты отсутствия пула добавлены отдельной миграцией Localization и в общий fallback-шаблон без перезаписи пользовательских переводов. После установки на уже зависший сервер перезапустить сервер или перезагрузить карту, чтобы заново запустить игровой lifecycle. Проверить: пустая карта дольше 45 минут → подключение человека → появление отсчёта заражения; затем выход всех игроков и повторное подключение. При заполненном пуле время ротации не расходуется без людей; при пустом пуле карта бессрочна. Дополнительно проверить заполнение и очистку пула без перезапуска, включая очистку во время голосования.

## Проверка в CS2 перед включением

.NET-сборка и тесты не заменяют компиляцию Panorama. Нужно скомпилировать ресурсы актуальными Workshop Tools, смонтировать общий VPK и проверить клики, ESC, страницы, RTV при открытом магазине/ножах, hot reload активного vote, stock и установленную Workshop-карту. Также проверить подключение PostgreSQL, заполнение каталога и права `maprotation.admin`. На рабочий сервер изменения автоматически не устанавливаются.
