# Ротация карт Elysium

`MapRotation.Core` управляет временем карты, provisional nextmap, номинациями, RTV, голосованием и сменой карты. Все интерактивные экраны используют `CustomHud.Api.ICustomHudMenuApi`. Flute CMS и ограничения карт по количеству игроков в эту версию не входят.

## Установка

1. Выполнить `pwsh ./scripts/build-package.ps1 -Configuration Release`. Установить собранные папки плагинов из `dist/Release/plugins`. Обновляются также `CustomHud.Core`, `CustomKnife.Core`, `Shop.Core` и `Localization.Core`; они согласуют захват ввода через общий API.
2. Создать подключение SwiftlyS2 с именем `map_rotation`, драйвером `postgresql` и отдельной игровой БД этого сервера. Формат подключения такой же, как у `custom_knife` и `shop`. Секреты в репозитории не хранятся. Плагин сам применяет EF-миграцию схемы `map_rotation`.
3. Заполнить `map_rotation.maps` только установленными картами. По умолчанию каталог пуст: плагин не добавляет неизвестные Zombie-серверу карты. Пример SQL ниже следует адаптировать под свой каталог.
4. Добавить **содержимое** `CustomHud.Core/resources/hud/menus/content/` в существующий addon HUD. Скомпилировать XML/CSS Workshop Tools и добавить полученные ресурсы в общий VPK. Отдельный VPK MapRotation не требуется. У сервера и клиентов должен быть одинаковый обновлённый VPK.
5. Обновлённый `Localization.Core` добавляет ключи `MapRotation.*`; ru/en присутствуют и в fallback. Выдать администраторам `maprotation.admin`.

```sql
INSERT INTO map_rotation.maps
    (key, display_name, map_name, workshop_id, sort_order)
VALUES
    ('gorodok', 'Gorodok', 'zm_gorodok_cs2_v1', 3100743780, 10);
-- Добавьте остальные установленные карты. При allow_same_map=false одна текущая карта
-- не образует ротацию; в каталоге нужна ещё одна допустимая карта.
UPDATE map_rotation.settings
SET configuration_version = configuration_version + 1 WHERE id = 1;
```

Настройки по умолчанию соответствуют ТЗ: 45 минут на карту, голосование за 5 минут до конца на 20 секунд, 6 кандидатов, 3 слота номинаций, RTV 60% с минимумом 3 голоса и 4 игрока, задержка RTV 5 минут. Настройки и каталог перечитываются фоново раз в `refresh_interval_seconds` (15 секунд).

## Команды

| Команда | Поведение |
|---|---|
| `!timeleft` | Карточка MM:SS; после deadline — последний раунд |
| `!nextmap` | Карточка следующей карты |
| `!rtv` | Один запрос на SteamID; при активном vote повторно открывает HUD |
| `!nominate` | HUD номинаций с пагинацией |
| `!nominate <key или map_name>` | Добавить или заменить свою номинацию |
| `maprotation_status` | JSON текущего состояния |
| `maprotation_reload` | Запросить фоновое обновление настроек и каталога |
| `maprotation_vote` | Начать общее голосование, если следующая карта ещё не зафиксирована |
| `maprotation_setnext <key или map_name>` | Зафиксировать карту администратором и отменить текущий vote |
| `maprotation_change <key или map_name>` | Проверить и сменить карту через Engine API |

Последние пять команд требуют `maprotation.admin` для игрока; серверная консоль разрешена. Параметры команд никогда не конкатенируются в команду движка: сначала находится запись каталога и проверяется `Engine.IsMapValid`.

## Правила работы

- Состояния: Loading → Playing → Voting → NextMapSelected → FinalRound → ChangingMap. На deadline существующий vote может завершиться в FinalRound; `round_end` завершает его перед сменой карты. Warmup и GameCommencing не завершают последний раунд.
- Время считается через `TimeProvider`. Горячая перезагрузка на той же фактической карте восстанавливает исходный deadline, кандидатов, голоса и nextmap. Настройка длительности применяется со следующей карты.
- Успешный RTV с `end_of_round` делает текущий раунд последним. `immediate` поддерживается явно; `rtv_change_delay_seconds` применяется после соответствующего события. Timeout последнего раунда вызывает принудительную смену с предупреждением.
- Смена отправляется на следующем world update, после завершения обработчиков game-event. Перед отправкой повторно проверяется карта. Отсутствие map-load в течение 30 секунд считается неудачей; выбирается другая допустимая карта с ограничением частоты повторов.
- Номинации группируются по числу игроков. Из лидеров берутся `nomination_slots`, оставшиеся кандидаты выбираются по весам без повторов. Равенство голосов/номинаций решает внедряемый RNG. Кандидаты активного vote не меняются при reload, но отключённая или удалённая карта не может победить.
- Cooldown проверяется по истории завершённых карт. При нехватке кандидатов ослабляется сначала индивидуальный, затем общий cooldown. Если auto-пул пуст, явно заданный `fallback_map_id` может использоваться даже вне auto-пула; disabled, current при запрете повторов и неустановленные карты запрещены всегда. Fallback не попадает в номинации или vote в обход их флагов.
- Один SteamID имеет одну номинацию, один RTV и один действующий бюллетень. Повторный выбор заменяет бюллетень. Disconnect/потеря права участия удаляет участие; подключение и изменение количества игроков пересчитывает порог. При `exclude_bots=false` боты учитываются в численности, но не создают голоса.
- `mp_timelimit`, `mp_maxrounds`, `mp_winlimit`, `mp_match_end_changelevel` и `mp_match_end_restart` удерживаются в 0, чтобы нативная ротация не конкурировала с модулем. При выгрузке исходные значения восстанавливаются, если их не изменил другой владелец.
- SQL не выполняется из vote/click/render/tick. Фоновый worker сохраняет immutable-снимки не чаще `refresh_interval_seconds`; выгрузка делает финальное сохранение. `rotation-state.json` записывается атомарно и содержит незаписанную историю/результаты для повтора после отказа БД. Повтор записи истории идемпотентен.
- Каталог и settings читаются одной транзакцией RepeatableRead. Ошибка БД или невалидная конфигурация сохраняет последний корректный снимок.

## HUD

Ресурсы называются `elysium_menu_v1.xml/css`, как прямо указано в ТЗ. Суффикс — версия общего шаблона, не версия компилятора Valve. Корневая панель без id; JS и обработчики `onactivate` отсутствуют.

Один fullscreen menu на игрока. Vote имеет Critical priority, номинации — Normal. Открытие общего меню закрывает HUD магазина и ножей. ESC закрывает интерфейс, но не удаляет уже поданный голос; `!rtv` открывает активное голосование снова. Новая страница получает новую entity, поэтому отложенный клик старой страницы не выбирает другой пункт.

Дизайн работает без обязательных изображений карт: используется нейтральная пиктограмма. Карточки `!timeleft`/`!nextmap`/`!rtv` отправляются через существующий API баннеров. Отсутствие ресурсов меню не отключает сообщения/баннеры; пользователю приходит локализованное уведомление в чат. Текстовые команды не заменяются стандартным Swiftly Menu API.

Макеты: [общий вид](../docs/map-rotation/previews/overview.png), [номинации](../docs/map-rotation/previews/nomination.png), [голосование](../docs/map-rotation/previews/vote.png), [результат](../docs/map-rotation/previews/result.png), [компактные карточки](../docs/map-rotation/previews/cards.png). Это браузерная адаптация фактических XML/CSS с данными примера, не игровые скриншоты. Генератор: `python scripts/hud-preview/render-menu.py`, затем `node scripts/hud-preview/capture.mjs` с установленным Playwright. `HUD_PREVIEW_CHROMIUM` позволяет указать локальный Chromium.

## Проверка в CS2 перед включением

.NET-сборка и тесты не заменяют компиляцию Panorama. Нужно скомпилировать ресурсы актуальными Workshop Tools, смонтировать общий VPK и проверить клики, ESC, страницы, RTV при открытом магазине/ножах, hot reload активного vote, stock и установленную Workshop-карту. Также проверить подключение PostgreSQL, заполнение каталога и права `maprotation.admin`. На рабочий сервер изменения автоматически не устанавливаются.
