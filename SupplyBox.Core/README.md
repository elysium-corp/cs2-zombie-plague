# SupplyBox 1.0.1

Ящики снабжения для Zombie Plague: реальные награды, настройки в PostgreSQL и редактор Flute CMS `ElysiumSupplyBox`.

Версия 1.0.1 исправляет остановку запуска SwiftlyS2 с `GlobalVars is null.`: до первой карты плагин ждёт `OnMapLoad`, а при reload на работающей карте сразу загружает её точки. `supply_status` показывает `waiting_for_map`, пока карта недоступна.

## Установка

1. Соберите сервер командой `pwsh scripts/build-package.ps1 -Configuration Release` и установите содержимое готового `dist/Release/plugins/SupplyBox.Core`. У плагина новые зависимости: `Economy.Api` и `CustomEquipment.Api`; устанавливайте весь каталог, включая `Npgsql.dll` и API-сборки. На сервере должны работать Economy, CustomEquipment, Localization и ZombiePlague.
2. Подключение SwiftlyS2 `elysium_zp_server_1` должно вести в PostgreSQL игрового сервера. При первом запуске нужны права создания схемы и объектов. Пароли остаются в конфигурации подключений SwiftlyS2.
3. Плагин создаёт схему `supply_box` и начальную конфигурацию, затем один раз читает старые `SupplyBox.Core/SupplyBox/<map>.json`. Файлы не изменяются и не удаляются. Автоматически созданные старой версией пустые файлы пропускаются.
4. Установите модуль сайта из репозитория `website-flute-cms`, папка `app/Modules/ElysiumSupplyBox`, и выберите в нём подключение к той же БД. Админка: `/admin/elysium-supply-box`, право `admin.servers`.
5. Начните новый раунд Zombie Plague и выполните `supply_status`. По умолчанию первая волна появляется через 30 секунд после начала режима, если есть хотя бы один живой человек.

Если карты ещё нет в конфигурации, по умолчанию плагин берёт до 64 существующих `info_player_counterterrorist` и сохраняет их координаты в БД. Это стартовые точки: проверьте высоту и доступность мест на своей карте. Автоматическое добавление можно выключить. Уже существующие пустые или выключенные карты не заполняются заново.

## Хранение и синхронизация

Все общие правила, типы ящиков, награды, карты и точки находятся в `supply_box.configuration.data` (`jsonb`). Полная конфигурация меняется атомарно с увеличением `version`. Конкурирующие изменения из игры и сайта проверяют ожидаемую версию, поэтому одна вкладка не затирает другую. Представления `supply_box.maps`, `spawn_points`, `box_types`, `loot` доступны для чтения SQL.

Конфигурация загружается при старте, смене карты и каждые 30 секунд. Новые правила и точки используются последующими волнами; уже созданный ящик сохраняет свои награды и параметры. Задержка первого выпадения применяется при начале следующего раунда. Для немедленного перечитывания есть `supply_reload`. Новые модели требуют смены карты для precache; ресурсы должны быть доступны серверу и клиентам.

Игровой редактор `!supply` / `supply` требует право SwiftlyS2 `supply_box.admin.edit`. Добавление и удаление точек подтверждаются только после успешной записи в БД. При отказе БД редактирование не записывается в локальный файл.

## Резервный конфиг

Плагин **не создаёт и не перезаписывает файлы конфигурации**. Вкладка «Резервная копия» сайта по запросу скачивает `supply_box.json` с полной конфигурацией, включая координаты и награды. Разместите файл вручную в:

```text
addons/swiftlys2/configs/plugins/SupplyBox.Core/supply_box.json
```

Это `Core.Configuration.BasePath/supply_box.json`. Пример лежит в `resources/templates/supply_box.example.json`; он не активируется автоматически. При первом создании записи БД существующий корректный fallback используется как начальная конфигурация. Старый формат с корневым `SupplyBox` также читается для миграции.

Порядок при загрузке: доступная БД → корректный fallback → предыдущий снимок в памяти → встроенные настройки. Ошибочный fallback не блокирует доступную БД. После восстановления соединения периодическая загрузка снова выбирает БД. Экспорт на сайте отмечает скачанную версию, но не подтверждает установку файла на сервере; после изменений скачайте и установите новую копию.

## Настройки

| Группа | Возможности |
| --- | --- |
| Волны | Первое выпадение, интервал, случайная добавочная задержка, шанс, число ящиков за волну |
| Ограничения | Одновременно на карте, за раунд, за карту, с заданного раунда, каждый N-й раунд |
| Игроки и режимы | Минимум игроков и живых людей/зомби, учёт ботов, Survivor и Nemesis |
| Падение | Высота, скорость, модель ящика, необязательные парашют и звук |
| Подбор | Разрешённые стороны, радиус, срок жизни после посадки, лимит и пауза на игрока, предел здоровья/брони |
| Типы ящиков | Включение, вес выбора, модель, количество розыгрышей, уникальные награды |
| Карты и точки | Включение, 28 переопределений правил, разрешённые типы, радар в Flute, XYZ и углы, вес, закреплённый тип ящика |

Награды: деньги Economy, здоровье, броня, стандартное оружие CS2 из списка, предметы CustomEquipment. Для числовых наград задаются минимум и максимум; для всех наград — относительный вес. Оружие/снаряжение выдаётся по одному предмету за розыгрыш. Обычное оружие заменяет соответствующий слот; зомби его не получают. CustomEquipment сохраняет собственные ограничения использования. Недоступные игроку награды исключаются из розыгрыша. Если ничего выдать не удалось, ящик остаётся.

## Проверка на игровом сервере

1. `supply_status`: источник `database`, текущая карта и число точек. Статус объясняет ожидание раунда, лимиты, условия игроков или отсутствие точек.
2. Новый ZP-раунд: ящик появляется, падает до заданного Z, подбирается после посадки и выдаёт награду. Конец раунда удаляет оставшиеся ящики.
3. Измените точку и награду на сайте, сохраните, выполните `supply_reload`; следующая волна использует изменения.
4. На тестовом сервере проверьте отказ БД с заранее установленным fallback, затем восстановление подключения. Редактор не должен сообщать об успешной записи во время отказа.

Автотесты конфигурации и правил: `dotnet test SupplyBox.Core.Tests -c Release`. Полноценная проверка физических сущностей и установленного addon требует запущенного CS2.

## Радар и правила карты — 1.1.0

Обновляйте серверный плагин до 1.1.0 перед ElysiumSupplyBox 1.1.0. Плагин принимает документы версий 1 и 2; при записи используется версия 2. Старые ChanceDrop/MaxCountTogether продолжают читаться, явные значения Maps[].Overrides имеют приоритет, затем используются общие правила. Настройки карты не меняют глобальный Enabled.

В Flute можно загрузить радар и overview .txt, добавлять точки кликом и перемещать маркеры. Maps[].Radar сохраняет привязку и идентификатор изображения, DefaultPointZ — высоту новых точек. Сами изображения лежат в supply_box.radar_images в PostgreSQL и игровому серверу не нужны. Новые поля сохраняются при правках через !supply и входят в JSON fallback; изображения резервируйте вместе с БД. Установленный плагин 1.0 отклонит документ версии 2, поэтому откат требует обратной миграции.

Maps[].AllowedBoxTypes = null разрешает все глобально доступные типы, пустой список запрещает все; закреплённый в точке тип также обязан входить в список. Разное содержимое для карт задаётся разными типами ящиков. Overrides поддерживает интервалы, шанс, лимиты, условия раундов и игроков, параметры падения, подбора и парашюта. Значения 0 и false являются явными настройками, null наследует общее. Модели парашютов из настроек карт включаются в precache.

Радар определяет только X/Y. Z задаётся отдельно по игровой карте и означает центр ящика после посадки; нулевое значение не включает поиск пола. Перетаскивание сохраняет Z, а изменения применяются к следующим ящикам после обновления конфигурации (до 30 секунд или supply_reload). Уже запланированная волна сохраняет свой таймер; новый интервал применяется после неё.
