# CustomEquipment.Core

Версия `0.4.1` хранит в PostgreSQL огнестрельное оружие, пять встроенных гранат,
лазерную мину и два независимых магазина экипировки. Реализации поведения
остаются в C#, а изменяемые параметры, доступность, цены, модели и порядок
управляются через Game CMS.

## База данных

Плагин использует подключение Swiftly `elysium_zp_server_1` и схему
`custom_equipment`:

- `weapons` — все игровые, магазинные и визуальные параметры оружия;
- `weapon_sounds` — звуковые события и заменяемые штатные sound events;
- `weapon_sound_files` — `.vsnd` по трекам `01`–`99`;
- `gameplay_items` — параметры `barrier_nade`, `fire_nade`, `frost_nade`,
  `jump_nade`, `shake_nade` и `laser_mine`; специфичные значения поведения
  хранятся в проверяемом JSONB-объекте `settings`;
- `shop_settings` — отдельные общие настройки витрин `human` и `zombie`;
- `shop_categories` — независимые категории двух витрин;
- `shop_listings` — товары, описания, цены и лимиты за раунд и карту;
- `shop_role_limits` — расширенные общие лимиты по привилегиям `Admin.Core`;
- `shop_products` — встроенные товары без игровой сущности, включая броню.

Первичная EF Core-миграция создаёт настройки, категории и встроенный тип товара
«Броня», но не добавляет ни один товар в витрины. Пушки, гранаты, мину и броню
нужно явно добавить в магазин через Game CMS. Обновляющая миграция удаляет
только автоматически созданные старой версией позиции и сохраняет товары,
которые администратор добавил позднее.

До первой успешной загрузки гранаты и мина используют встроенные значения,
но не появляются в магазине без явной записи витрины.
На первом запуске огнестрельное оружие попадёт в runtime-каталог только после
успешной загрузки справочника. Каталоги обновляются при запуске плагина и один
раз при каждой
загрузке карты; периодический polling отсутствует. Неудачная повторная загрузка
не очищает уже активные снимки.

Магазин открывается людям и зомби, но не наблюдателям; покупать может только
живой игрок. После заражения,
лечения либо перехода в особую роль открытое меню перестраивается под текущую
витрину. Счётчики покупок людей и зомби независимы. Ноль в любом лимите означает
отсутствие ограничения; при совпадении нескольких привилегий применяется самый
свободный общий лимит. Проверка привилегий выполняется из runtime `Admin.Core`
при покупке и не обращается к PostgreSQL.

## Перезагрузка

Выполните только из серверной консоли:

```text
custom_equipment_reload
```

Команда запускает обновление немедленно. Без неё изменения применятся при
следующей загрузке карты. Новые выдачи используют обновлённый снимок. Уже
выданные экземпляры оружия с ID,
который остался в каталоге, сохраняют старые параметры; удалённый ID перестаёт
проходить проверку использования.

## Звуки

Поддерживаемые `trigger`:

```text
fire
reload
empty
draw
inspect
zoom
silencer_on
silencer_off
```

Плагин воспроизводит `event_name` через Swiftly SoundEvent. Если заполнено
`replaces_event_name`, сетевое сообщение именно этого штатного события
подавляется для отслеживаемого кастомного оружия, чтобы звуки не накладывались.

Общий скомпилированный ресурс должен быть установлен как:

```text
soundevents/game_sounds_elysium_weapons.vsndevts_c
```

Flute-модуль `ElysiumEquipments` генерирует исходный `.vsndevts`. Его нужно
скомпилировать штатными Source 2 Workshop Tools / ResourceCompiler. После
добавления новых ресурсов требуется смена карты или перезапуск для precache.

## Миграции для разработки

Design-time connection задаётся переменной `CUSTOM_EQUIPMENT_DB_CONNECTION`.

```bash
dotnet ef migrations add <Name> \
  --project CustomEquipment.Core/CustomEquipment.Core.csproj \
  --configuration Migrations \
  --context CustomEquipmentDbContext
```
