# CustomEquipment.Core

Версия `0.6.1` хранит в PostgreSQL огнестрельное оружие, пять встроенных гранат
и лазерную мину. Реализации поведения остаются в C#, а изменяемые игровые
параметры, доступность, модели и порядок управляются через Game CMS. Экономика
полностью вынесена в `Shop.Core`: каталог экипировки не загружает цены и не
выполняет покупки.

Названия оружия и игровых предметов обязаны ссылаться на ключи
`Localization.Core`. Если ключ ещё не опубликован, сервер безопасно показывает
сохранённый `display_name`. Поля `image_url` используются Game CMS для превью и
не загружаются игровым runtime.

## База данных

Плагин использует подключение Swiftly `elysium_zp_server_1` и схему
`custom_equipment`:

- `weapons` — игровые и визуальные параметры оружия;
- `weapon_sounds` — звуковые события и заменяемые штатные sound events;
- `weapon_sound_files` — исторические данные старого редактора; runtime-каталог их больше не загружает;
- `gameplay_items` — параметры `barrier_nade`, `fire_nade`, `frost_nade`,
  `jump_nade`, `shake_nade` и `laser_mine`; специфичные значения поведения
  хранятся в проверяемом JSONB-объекте `settings`.

Исторические столбцы `item_price`/`ammo_price` и таблицы старого магазина пока
сохраняются только для безопасного обновления существующих установок.
`CustomEquipment.Core` их не читает. Миграция `Shop.Core` переносит доступные
старые позиции в отдельную схему `shop`, после чего цены, категории, лимиты,
cooldown и привилегии обслуживаются только новым модулем.

До первой успешной загрузки гранаты и мина используют встроенные значения.
На первом запуске огнестрельное оружие попадёт в runtime-каталог только после
успешной загрузки справочника. Каталоги обновляются при запуске плагина и один
раз при каждой
загрузке карты; периодический polling отсутствует. Неудачная повторная загрузка
не очищает уже активные снимки.

Настройка витрин и правила их runtime-поведения описаны в
[`Shop.Core/README.md`](../Shop.Core/README.md).

Ограничения по привилегиям относятся к покупке в `Shop.Core`. Подобранный
экземпляр сохраняет кастомную модель, имя, подкласс, урон, звуки и параметры
у нового владельца независимо от его привилегий. После подбора и экипировки
плагин повторно применяет параметры экземпляра, сохраняя оставшиеся патроны
в магазине и резерве. Ограничения стороны человек/зомби и запрет удалённых
из каталога предметов продолжают действовать.

## Перезагрузка

Выполните только из серверной консоли:

```text
custom_equipment_reload
```

Команда запускает обновление немедленно. Без неё изменения применятся при
следующей загрузке карты. Новые выдачи используют обновлённый снимок. Уже
выданные экземпляры оружия с ID,
который остался в каталоге, сохраняют старые параметры; удалённый ID перестаёт
проходить проверку использования.

## Отдача и точность оружия

В `0.8.0` таблица `custom_equipment.weapons` получает два необязательных
JSONB-поля: `recoil` и `accuracy`. Миграция выполняется при запуске плагина;
существующие записи получают SQL `NULL`. Старые C#-реализации `IWeapon`
продолжают работать: новые свойства по умолчанию возвращают `null`.
В `WeaponItemBase` можно переопределить `WeaponRecoil` и `WeaponAccuracy`.

Значения применяются через тот же `WeaponBaseVData`, что уже используется
для боезапаса, скорострельности и пробития. Они задаются **абсолютно**, в
единицах движка: это не проценты и не множители. Повторное применение при
подборе или экипировке не умножает их и не пополняет патроны.

Массив `[основной, альтернативный]` задаёт два режима оружия
(например, без зума и в зуме). Массив из одного значения изменяет только
основной режим. Отсутствующее поле или `[]` не меняет соответствующие значения;
у скалярных полей также разрешён `null`. SQL `NULL` и `{}` не задают
переопределений. Все числа должны быть конечными; отрицательные значения
разрешены только для `angle`. Неизвестные поля, массивы длиннее двух элементов
и неверные значения отклоняют обновление каталога, сохраняя предыдущий снимок.

| Поле | Назначение |
| --- | --- |
| `recoil.magnitude` | Сила импульса отдачи и увода прицеливания |
| `recoil.magnitude_variance` | Случайное отклонение силы отдачи |
| `recoil.angle` | Направление отдачи в градусах от `-180` до `180`; `0` — вверх |
| `recoil.angle_variance` | Разброс направления отдачи от `0` до `180` градусов |
| `accuracy.spread` | Базовый случайный разброс пуль |
| `accuracy.inaccuracy_stand`, `inaccuracy_crouch` | Неточность стоя и сидя |
| `accuracy.inaccuracy_move`, `inaccuracy_fire` | Неточность при движении и накопление неточности от выстрелов |
| `accuracy.inaccuracy_jump`, `inaccuracy_land`, `inaccuracy_ladder` | Неточность в прыжке, при приземлении и на лестнице |
| `accuracy.inaccuracy_jump_initial`, `inaccuracy_jump_apex`, `inaccuracy_reload` | Общие для обоих режимов числа: неточность в начале/верхней точке прыжка и от перезарядки |

Пример настройки (замените `your_weapon_id` на `internal_name` оружия):

```sql
UPDATE custom_equipment.weapons
SET recoil = '{
      "magnitude": [15, 10],
      "magnitude_variance": [0, 0],
      "angle": [0, 0],
      "angle_variance": [10, 5]
    }'::jsonb,
    accuracy = '{
      "spread": [0.001, 0.0005],
      "inaccuracy_stand": [0.002, 0.001],
      "inaccuracy_crouch": [0.001, 0.0005],
      "inaccuracy_fire": [0.003, 0.002]
    }'::jsonb,
    updated_at = CURRENT_TIMESTAMP
WHERE internal_name = 'your_weapon_id';
```

Для минимального отклонения пуль нужно уменьшать и `spread`, и составляющие
`inaccuracy`. Один `spread = [0, 0]` не убирает неточность от движения и очереди.
Отдача также смещает направление стрельбы: для нулевого импульса обнулите
одновременно `magnitude` и `magnitude_variance`. Пример обнуления всех
перечисленных составляющих в обоих режимах:

```sql
UPDATE custom_equipment.weapons
SET recoil = '{"magnitude":[0,0],"magnitude_variance":[0,0]}'::jsonb,
    accuracy = '{
      "spread":[0,0],
      "inaccuracy_stand":[0,0],
      "inaccuracy_crouch":[0,0],
      "inaccuracy_move":[0,0],
      "inaccuracy_fire":[0,0],
      "inaccuracy_jump":[0,0],
      "inaccuracy_land":[0,0],
      "inaccuracy_ladder":[0,0],
      "inaccuracy_jump_initial":0,
      "inaccuracy_jump_apex":0,
      "inaccuracy_reload":0
    }'::jsonb,
    updated_at = CURRENT_TIMESTAMP
WHERE internal_name = 'your_weapon_id';
```

После обновления выполните `custom_equipment_reload` в серверной консоли и
выдайте оружие заново. Это параметры **подкласса**: у экземпляров, использующих
один и тот же VData, значения общие. Для разных профилей нужны разные
подклассы в ресурсах оружия; одинаковый `subclass_name` с разными настройками
будет приводить к их перезаписи при выдаче/экипировке. Удаление переопределения
не восстанавливает уже изменённый VData: для возврата к данным ресурсов
после установки SQL `NULL` смените карту.

Настройки меняют серверный VData. Клиентское предсказание и анимация модели
требуют согласованных ресурсов оружия; серверная настройка не заменяет
клиентский VData/VPK и не меняет пользовательский `cl_crosshair_recoil`.
Остаточное состояние отдачи/точности, серверные cvar и другие плагины также
могут влиять на текущий выстрел. Проверять попадания следует на свежевыданном
оружии, включая очередь, движение и зум.

Редактор Game CMS находится в другом репозитории: здесь добавлены серверная
схема, API и применение настроек. Пока редактор не поддерживает новые поля,
их можно менять указанными SQL-запросами.

## Редкость

В `0.6.2` оружие, гранаты и лазерная мина предоставляют редкость через общий
контракт `IHasRarity` в `CustomEquipment.Api.Data.Contracts`.
`Shop.Core 1.2.2` использует это значение
для цвета названия в меню. Обновляйте оба плагина вместе с общей `CustomEquipment.Api`.

## Звуки

Поддерживаемые `trigger`:

```text
fire
reload
empty
draw
inspect
zoom
silencer_on
silencer_off
```

Плагин воспроизводит `event_name` через Swiftly SoundEvent и передаёт
`weapon_sounds.volume` в `SoundEvent.Volume` (`public.volume`) перед `Emit()`.
Для каждого триггера оружия задаётся одно звуковое событие. Несколько файлов
и их случайный выбор настраиваются внутри самого Sound Event средствами
Source 2; плагин воспроизводит это событие с заданной громкостью.

Громкость должна быть конечным числом от `0` до `10`; `0` — без звука,
`1` — исходная громкость. Список `.vsnd`, тип, высота и дополнительные свойства
старого редактора для загрузки события больше не требуются. Если заполнено
`replaces_event_name`, сетевое сообщение именно этого штатного события
подавляется для отслеживаемого кастомного оружия, чтобы звуки не накладывались.

Общий скомпилированный ресурс должен быть установлен как:

```text
soundevents/game_sounds_elysium_weapons.vsndevts_c
```

Исходные события готовятся в Source 2 Workshop Tools / ResourceCompiler.
`ElysiumEquipments 1.16.0` хранит только привязку триггера, имя события и
громкость; экспорта и автоматической генерации `.vsndevts` больше нет.
Изменение громкости требует обновления каталога и новой выдачи оружия, без
пересборки VPK. После добавления новых ресурсов нужна смена карты для precache.

Триггер `fire` запускается по сетевому сообщению стрельбы `CMsgTEFireBullets`
для активного кастомного оружия. Типы звука `WEAPON_SOUND_EMPTY` и
`WEAPON_SOUND_SECONDARY_EMPTY` не запускают `fire`; для холостого щелчка
сохранён отдельный триггер `empty`. Остаток патронов после выстрела не
проверяется, поэтому последний патрон также воспроизводит звук.

В SwiftlyS2 `1.4.6-beta.8` и проверенном `master` (`ce37bdc8`) нет отдельных
GameEvents `clip_in`/`clip_out`: доступен общий `EventWeaponReload`.
Триггер звука `reload` отслеживается по переходу активного оружия в состояние
`CCSWeaponBase.InReload` на серверном тике. Это учитывает ручную и автоматическую
перезарядку после опустошения магазина и воспроизводит звук один раз за начало
перезарядки. Пустой магазин сам по себе не запускает звук.
Анимационное событие `AE_CL_EJECT_MAG` относится к клиенту и не является
готовой серверной подпиской на извлечение магазина.
`WeaponSound_t` содержит `WEAPON_SOUND_RELOAD`, а `CCSUsrMsg_ReloadEffect`
не содержит отдельной фазы извлечения или вставки магазина. Добавление этих
триггеров требует проверки анимации/сетевых сообщений конкретной модели;
обычная подписка на `weapon_reload` не даёт точных моментов `clip in/out`.

Источники SwiftlyS2: [EventWeaponReload](https://github.com/swiftly-solution/swiftlys2/blob/ce37bdc8f26ce98059eb2cef72bbd479c4504b1e/managed/src/SwiftlyS2.Generated/GameEvents/Interfaces/EventWeaponReload.cs),
[WeaponSound_t](https://github.com/swiftly-solution/swiftlys2/blob/ce37bdc8f26ce98059eb2cef72bbd479c4504b1e/managed/src/SwiftlyS2.Generated/Schemas/Enums/WeaponSound_t.cs),
[SoundEvent.Volume](https://github.com/swiftly-solution/swiftlys2/blob/ce37bdc8f26ce98059eb2cef72bbd479c4504b1e/managed/src/SwiftlyS2.Shared/Modules/Sounds/SoundEvent.cs).


## Миграции для разработки

Design-time connection задаётся переменной `CUSTOM_EQUIPMENT_DB_CONNECTION`.

```bash
dotnet ef migrations add <Name> \
  --project CustomEquipment.Core/CustomEquipment.Core.csproj \
  --configuration Migrations \
  --context CustomEquipmentDbContext
```
